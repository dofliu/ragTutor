命題檢索：把段落拆成一條一條獨立的事實

手冊的一個段落常常混了五、六個要點。技師只想知道「PT-203 出現時先檢查什麼」，段落級檢索卻把整段帶進上下文，其餘句子都是雜訊。命題檢索（Proposition Retrieval）在建索引時，先請模型把段落改寫成自成一句的原子事實，再以這些命題為檢索單元，檢索單元變小、變精準，上下文也更省。

🎬 動畫：從整段，到一條一條事實

🧩 重點整理

檢索單元可以調整文件、段落、句子之外，還可以用「命題」。Dense X Retrieval 這篇論文系統性比較了不同檢索粒度對檢索與問答的影響。
命題要自成一句每條只講一個獨立事實，並把代名詞、省略的主詞補回來。只切成句子，「它」仍然不知道指誰。
建索引時做，查詢時不加成本命題化是離線步驟，要呼叫模型；查詢流程與一般向量檢索相同。手冊改版時要重跑受影響的段落。
拆細也有代價命題可能抽錯、遺漏條件，並切掉前因後果。保留出處段落編號，需要時補回父段落（第 008 堂）。

🧪 互動範例：段落、句子、命題三種粒度

知識庫是 4 個虛構的《OW-8 運維手冊》段落（共 18 句）。三種做法檢索同一批內容：A 段落、B 原句（只切句，保留「它」）、C 命題（句子已補回主詞，是預先寫好的，真實系統由模型生成）。檢索是瀏覽器內真的在算（BM25，中文用二字詞），各取前 3 名。請看需要的證據排第幾、帶進上下文的字數有多少。

A. 段落粒度
B. 原句粒度（只切句）
C. 命題粒度（補回主詞）

💻 程式範例（Python）

下面是最小實作：用 claude-sonnet-5 把段落改寫成命題（離線，建索引時做一次），再以命題為單元做 BM25 檢索，並保留出處段落編號。範例以空白斷詞，中文實務上請換成適合的斷詞器。

import json
import anthropic
from rank_bm25 import BM25Okapi

client = anthropic.Anthropic()

PASSAGES = [
    "PT-203 表示旋角馬達過溫。它首次出現時，系統會自動降載。此時應先檢查冷卻風扇與散熱片。",
    "GB-117 為高速軸軸承溫度過高。它出現時須先確認油位與油溫。若振動同時上升，應停機檢查。",
]

def propositionize(passage):
    prompt = ("請把下列段落拆成命題，每條命題：只含一個獨立事實、不可再拆、"
              "並把代名詞與省略的主詞補回，使其單獨閱讀也看得懂。"
              "只輸出 JSON 字串陣列。\n\n段落：" + passage)
    msg = client.messages.create(model="claude-sonnet-5", max_tokens=800,
                                 messages=[{"role": "user", "content": prompt}])
    return json.loads(msg.content[0].text)

# 建索引（離線）：每條命題記下出處段落編號
props = []
for pid, p in enumerate(PASSAGES):
    for t in propositionize(p):
        props.append({"text": t, "passage": pid})
bm25 = BM25Okapi([x["text"].split() for x in props])

# 查詢（線上）：與一般檢索相同，只是單元變成命題
q = "PT-203 首次出現會怎樣"
scores = bm25.get_scores(q.split())
best = sorted(range(len(props)), key=lambda i: -scores[i])[:3]
for i in best:
    print(props[i]["text"], "← 出處段落", props[i]["passage"])

實務上，命題化的結果要抽樣檢查（有沒有抽錯或漏掉條件），並用評估集（第 021 堂）比較「段落」與「命題」兩種索引的召回與答案品質。

⚠️ 命題檢索常見的坑 / 何時不該用

  • 命題抽錯：模型可能改寫掉門檻值、條件或單位。對安全相關的內容要抽樣審核，數值不要靠改寫。
  • 只切句、沒補主詞：「它」「該告警」留在句子裡，檢索就少了關鍵字。命題化必須包含指代還原。
  • 切掉前因後果：「先檢查風扇」的原因在前一句。可保留出處段落，檢索後視需要補回父段落。
  • 表格與步驟清單：順序與欄位關係拆開就失真。這類內容改用版面感知的切法（第 020 堂），不必硬拆成命題。
  • 索引成本：命題數遠多於段落數，嵌入、儲存與更新都增加。手冊常改版時要有重跑機制。
  • 不是一定更好：效果隨資料與檢索器而異。上線前用自己的評估集比較，不要照搬論文結論。
風場、機型、手冊內容、告警代碼與數據皆為虛構，實際作業以原廠手冊與現場規範為準。互動範例的命題是預先寫好的，不是真實的模型輸出。

延伸閱讀：Chen 等人，Dense X Retrieval: What Retrieval Granularity Should We Use?（arXiv 2312.06648）。

📝 小測驗

下列哪一個最符合「命題」的要求？

命題要只含一個獨立事實，並自成一句；A 的「它」要靠上下文，B 一句塞了多個事實。

命題化主要在哪個階段執行？

命題化是離線的索引步驟；查詢流程與一般向量檢索相同，但手冊改版時要重跑。
