第 004 堂進階約 14 分鐘

混合檢索：關鍵字抓不到的，向量抓得到；向量抓不到的，關鍵字抓得到

上一堂看到向量檢索怎麼找出「像不像」；但向量對型號、錯誤代碼這類罕見字串常常不夠敏感，而BM25 關鍵字檢索又完全不懂「換句話說」的同義句。混合檢索（Hybrid Search）不是二選一，而是兩種方法各自檢索一次，再用倒數排名融合（Reciprocal Rank Fusion, RRF）把兩份排序清單公平地合併成一份結果。

🎬 動畫：兩份清單，一次融合

🧩 重點整理

BM25 擅長精確詞彙型號、錯誤代碼、專有名詞這類罕見詞，BM25 靠逆文件頻率（IDF）能準確命中；但完全沒有字面重疊的內容，分數就是 0。
向量檢索擅長語意相近就算用詞不同，只要語意相近的內容也找得到；但對代碼、型號這類字串常常不夠敏感，容易漏掉或排名靠後。
RRF 只看名次不看分數兩種方法的分數尺度天差地遠，直接相加沒有意義；RRF 用每份清單裡的名次計算 1/(k+rank)，不需要校準原始分數。
混合檢索是業界常見預設Elasticsearch、OpenSearch、Azure AI Search、Weaviate、MongoDB Atlas 等系統都把 BM25 + 向量 + RRF 融合列為內建或建議做法。

🧪 互動範例：BM25 vs. 向量 vs. 混合 RRF，實際排一次

下面是一份虛構的「風禾家電」客服知識庫，共 30 筆，涵蓋洗衣機、冷氣、除濕機、冰箱、電鍋等常見故障代碼與保養問答。切換三種模式，並比較同一個查詢在 BM25、向量（TF-IDF 模擬）與混合 RRF 下，前幾名結果有什麼不同——特別留意每一筆結果在「另一種方法」裡排第幾名。

💻 程式範例（Python）

手動實作 BM25 評分、向量餘弦相似度，以及 RRF 融合。正式環境建議直接用 rank_bm25、Elasticsearch/OpenSearch，或向量資料庫本身內建的混合檢索功能，這裡只示範核心邏輯。

import math
from collections import Counter

# ① BM25：關鍵字檢索評分
def bm25_score(query_terms, doc_terms, avgdl, doc_freq, N, k1=1.5, b=0.75):
    tf = Counter(doc_terms)
    dl = len(doc_terms)
    score = 0.0
    for t in set(query_terms):
        f = tf.get(t, 0)
        if not f:
            continue
        n = doc_freq.get(t, 0)
        idf = math.log(1 + (N - n + 0.5) / (n + 0.5))
        score += idf * (f * (k1 + 1)) / (f + k1 * (1 - b + b * dl / avgdl))
    return score

# ② 向量檢索：doc_vecs 假設是嵌入模型已經算好的向量（例如 Voyage AI 等 embedding API）
def cosine(a, b):
    dot = sum(x * y for x, y in zip(a, b))
    na = math.sqrt(sum(x * x for x in a))
    nb = math.sqrt(sum(y * y for y in b))
    return dot / (na * nb + 1e-9)

def vector_search(query_vec, doc_vecs, k=50):
    scored = [(i, cosine(query_vec, v)) for i, v in enumerate(doc_vecs)]
    return sorted(scored, key=lambda x: -x[1])[:k]

# ③ RRF：把多份排序清單依名次融合，k 為平滑常數（原始論文使用 60）
def rrf_fuse(ranked_lists, k=60):
    scores = {}
    for ranked in ranked_lists:
        for rank, (doc_id, _) in enumerate(ranked, start=1):
            scores[doc_id] = scores.get(doc_id, 0.0) + 1 / (k + rank)
    return sorted(scores.items(), key=lambda x: -x[1])

# 用法：兩邊各自取一個夠大的候選池（例如 50 筆），再融合成最終 Top-k
bm25_ranked = sorted(
    [(doc_id, bm25_score(query_terms, doc_terms[doc_id], avgdl, doc_freq, N)) for doc_id in all_ids],
    key=lambda x: -x[1]
)[:50]
vector_ranked = vector_search(query_vec, doc_vecs, k=50)
final_top_k = rrf_fuse([bm25_ranked, vector_ranked], k=60)[:5]

⚖️ 檢索方式比較

純 BM25 關鍵字純向量檢索混合檢索 + RRF
擅長的查詢包含明確關鍵字、型號、代碼用詞不同但語意相近的自然語言問題兩種查詢都想兼顧
精確代碼／型號✅ 靠 IDF 準確命中稀有詞⚠️ 罕見字串不易學到好的表示，容易漏掉✅ 由 BM25 那份清單補上
同義詞／換句話說⚠️ 沒有字面重疊就完全找不到✅ 能抓到語意相近的內容✅ 由向量那份清單補上
分數尺度TF-IDF 類分數，無上限餘弦相似度，介於 0~1轉成名次後相加，不需校準原始分數
額外成本維護一份關鍵字索引維護一份向量索引與嵌入模型兩份索引都要維護，查詢也要跑兩次

⚠️ 混合檢索常見的坑 / 何時不該用

  • 候選池要夠大：如果 BM25、向量各自只取前 3 名就拿去融合，原本排在第 4 名以後的正確答案永遠沒機會被撈回來；實務上通常各自取數十筆候選，再融合成最終的 Top-k。
  • RRF 的常數 k 沒有標準答案：原始論文使用 k=60，是在融合多套大型檢索系統的情境下調校出來的值；k 越大，名次之間的分數差距越平滑，實際效果仍要用自己的資料實測調整。
  • 兩份索引要保持同步：文件新增、修改或刪除時，關鍵字索引與向量索引都要一起更新，只更新其中一份，兩邊的排序就會對不上。
  • RRF 只看名次，不看分數差距：如果想讓其中一種方法的意見更有份量（例如更信任向量檢索），需要改用加權分數融合並先把分數常態化，而不是直接套用 RRF。
  • 混合檢索救不回本來就很差的單一方法：如果中文分詞本身就切得亂七八糟，或嵌入模型完全不適合你的領域，融合出來的結果一樣不會好，問題要先從源頭處理。

📝 小測驗

為什麼 RRF 要把 BM25 分數與向量相似度都先轉成「名次」，而不是直接把兩種分數加起來？

BM25 是沒有上限的 TF-IDF 類分數，向量相似度則介於 0 到 1 之間，兩者的尺度與分布天差地遠。RRF 只依賴每份清單裡的名次（第幾名），不需要校準或常態化原始分數，就能公平地把多份排序清單融合在一起。

下列關於混合檢索（Hybrid Search）的敘述，何者最正確？

BM25 與向量檢索各自對應不同的查詢型態：BM25 靠字面重疊與稀有詞的 IDF，對精確代碼、型號特別準；向量檢索理解語意相近的內容，但對罕見字串不夠敏感。混合檢索讓兩者截長補短，而候選池太小（例如只取前 3 名）會讓某些原本該被融合進來的正確答案在源頭就被丟掉，RRF 也救不回來。
