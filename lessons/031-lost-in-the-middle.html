上下文排序：Lost in the Middle 與兩端排列

檢索找對了，答案卻還是漏東漏西？原因可能是段落放的位置。研究發現，語言模型在長脈絡中，關鍵資訊在開頭或結尾時表現最好，落在中間時明顯變差（Lost in the Middle）。對策很實際：少放幾段、把最相關的段落排在兩端、替段落編號並要求引用，最後用自己的模型掃描位置驗證。

🎬 動畫：把關鍵段落放到看得清楚的位置

🧩 重點整理

位置會影響結果Liu 等人發現：相關資訊在輸入的開頭或結尾時，表現通常最好；在中間時明顯下降，呈 U 形。檢索找對了，也可能因為擺錯位置而沒被用到。
越長越差同一篇研究也觀察到，輸入脈絡越長，整體表現越下降。把 top-k 開到最大不是保險，先用重排序與壓縮縮短脈絡。
兩端排列把排名最前的段落放在最前面，次相關的放在最後面，排名較低的放中間。只改順序、不增減內容，成本幾乎是零。
量過才算數不同模型對位置的敏感度不同。固定問題，只移動答案段落的位置，掃描開頭、中間、結尾的正確率；曲線平，就不必重排。

💻 程式範例（Python）

下面的程式做兩件事：reorder_ends 把依分數排序的段落改成兩端排列；position_sweep 把「答案段落」依序放在不同位置，用 anthropic 的 claude-sonnet-5 重複提問，統計答對率，驗證你的模型到底受不受位置影響。示範用 3 個干擾段落，實務上請放接近上線時的段落數並多跑幾次。

import anthropic

client = anthropic.Anthropic()

GOLD = "HY-120 作業安全：拆卸任何液壓管路前，先洩壓並執行上鎖掛牌（LOTO），確認壓力表歸零。"
FILLERS = [
    "HY-120 液壓站油壓偏低：蓄壓器氮氣預充壓力不足時，先量測預充壓力，再補充氮氣。",
    "HY-141 濾芯壓差過大：濾芯堵塞，依週期更換濾芯，備品料號 HY-FLT-01。",
    "HY-160 管路接頭滲油：O 型環老化，更換 O 型環並確認鎖固扭力。",
]
QUESTION = "WTG-18 液壓站油壓偏低，我要拆管路檢查，拆之前有什麼安全步驟？"

def reorder_ends(ranked):
    """ranked 依相關性由高到低；回傳最相關在最前、次相關在最後、其餘在中間"""
    front, back = [], []
    for i, doc in enumerate(ranked):
        (front if i % 2 == 0 else back).append(doc)
    return front + back[::-1]

def ask(docs):
    ctx = "\n".join(f"[{i+1}] {d}" for i, d in enumerate(docs))
    msg = client.messages.create(
        model="claude-sonnet-5", max_tokens=300,
        messages=[{"role": "user", "content":
            f"只根據下列手冊段落回答，並標註引用編號。\n\n{ctx}\n\n問題：{QUESTION}"}],
    )
    return msg.content[0].text

def position_sweep(trials=5):
    """固定問題與干擾段落，只移動答案段落的位置，統計答案是否提到上鎖掛牌"""
    for pos in range(len(FILLERS) + 1):
        docs = FILLERS[:pos] + [GOLD] + FILLERS[pos:]
        hits = sum(("上鎖掛牌" in ask(docs)) or ("LOTO" in ask(docs)) for _ in range(trials))
        print(f"答案放在第 {pos+1} 位：{hits}/{trials}")

# 實際使用：檢索 → 重排序（第 005 堂）→ 留前幾段 → 兩端排列 → 提問
ranked = [GOLD] + FILLERS            # 假設已依分數排好
print(ask(reorder_ends(ranked)))
position_sweep()

上面的判斷用字串比對，只是最小示範；正式評估請用第 021 堂的方法，並對每個位置重複多次取平均（position_sweep 為了精簡，每次判斷會呼叫模型兩次，可自行改成只呼叫一次後再檢查）。

⚠️ 上下文排序常見的坑 / 何時不該用

  • 把論文結論當成所有模型的定律：Lost in the Middle 是在特定任務與當時的模型上的觀察，不同模型、不同長度的敏感度都不同。要用自己的模型做位置掃描，別直接假設。
  • 只排序、不縮短：段落多到上千字時，兩端排列救不了整體變差的問題。先用重排序與壓縮控制長度。
  • 排序破壞原有脈絡：同一份手冊的步驟 1、2、3 被打散，模型可能讀不順。需要保持順序的內容，改用父子文件檢索（第 008 堂）整段回傳。
  • 忘了答案常需要多段：「排除步驟」加「安全注意事項」要同時出現，兩段都得放在好位置，不能只顧第一名。
  • 只有一兩段時不需要：k 很小時位置差異有限，排序的效益也小，先確認有問題再處理。
  • 評估要固定其他變因：掃描位置時，問題、段落內容與提示詞都要固定，只動位置，並重複多次，否則看不出是位置還是隨機性。
風場、機型、手冊與工單內容及數據皆為虛構，實際作業以原廠手冊與現場規範為準。互動範例的權重曲線為示意，不代表真實模型的行為與數字。

延伸閱讀：Liu 等人，Lost in the Middle: How Language Models Use Long Contexts（Transactions of the ACL，2024）。

📝 小測驗

檢索已經找到了正確段落，答案卻仍然漏掉關鍵資訊。依 Lost in the Middle 的觀察，最值得先檢查什麼？

研究發現相關資訊在開頭或結尾時表現較好、在中間時變差，且輸入越長整體越差。檢查位置與段落數，比盲目增加內容更有效。

「兩端排列」是怎麼放段落的？

兩端是模型最容易用到的位置，所以把最相關的段落放在那裡；排名較低的放中間，即使被忽略損失也較小。
