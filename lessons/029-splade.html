第 029 堂高階約 20 分鐘

SPLADE 學習式稀疏檢索：讓關鍵字檢索聽懂口語

BM25 要詞完全對上才算分，技師說「葉片轉不動」，手冊寫的卻是「煞車異常、角度卡住」，就查不到。稠密向量能補這個洞，卻看不出為什麼命中。SPLADE（Sparse Lexical and Expansion Model）讓語言模型替詞表上的每個詞打分並加上相關的擴展詞，輸出仍是稀疏向量，可以直接放進倒排索引：既聽得懂口語，又看得到是哪些詞對上。

🎬 動畫：從詞彙不匹配到學習式擴展

🧩 重點整理

輸出是「詞表上的加權」編碼器的 MLM 頭替詞表上每個詞打分，多數為 0。每個非零維度都對應一個真實的詞，所以能直接看出「為什麼命中」。
擴展詞解決詞彙不匹配「轉不動」會帶出「卡住」「煞車」等手冊常用的詞；文件端也會擴展，查詢與文件兩邊各補一些詞，更容易碰頭。
稀疏才能用倒排索引log(1+ReLU) 讓分數非負、不過度集中；稀疏正則（FLOPS）壓低非零詞數。只查「查詢裡有的詞」，延遲與 BM25 同類型。
代價在模型與索引要跑模型編碼文件與查詢；擴展詞讓索引變大、偶爾引入雜訊。領域用語差異大時，要微調或與稠密向量、BM25 混合使用。

🧪 互動範例：BM25 vs. 帶擴展的稀疏檢索

下面有 8 段《OW-8 運維手冊》片段（虛構）。選一個口語問題，比較只靠「詞對上」的 BM25，與「原詞＋擴展詞加權、內積計分」的稀疏檢索。你可以調整權重門檻：門檻越高，保留的擴展詞越少、索引越小，但可能又回到對不上的老問題。

這是簡化模擬：真實的 SPLADE 擴展詞權重由訓練好的模型輸出；這裡用一張手寫的擴展表代替，只是為了看清楚機制，不代表任何真實模型的行為。

💻 程式範例（Python）

用 Hugging Face transformers 實作 SPLADE 的編碼：取 MLM 頭的輸出，做 log(1+ReLU)，沿序列取最大值，只留非零的詞。範例用的 naver/splade-cocondenser-ensembledistil 是英文模型，所以手冊片段改用英文示意（內容仍為虛構）；中文語料請換成支援中文的稀疏模型或自行微調。檢索部分用字典模擬倒排索引。

import torch
from transformers import AutoTokenizer, AutoModelForMaskedLM

NAME = "naver/splade-cocondenser-ensembledistil"
tok = AutoTokenizer.from_pretrained(NAME)
model = AutoModelForMaskedLM.from_pretrained(NAME).eval()

def encode(text, top=None):
    """回傳 {詞: 權重}，只含非零的詞"""
    batch = tok(text, return_tensors="pt", truncation=True)
    with torch.no_grad():
        logits = model(**batch).logits                    # (1, 序列長度, 詞表大小)
    w = torch.log1p(torch.relu(logits))                    # log(1 + ReLU)
    w = (w * batch["attention_mask"].unsqueeze(-1)).max(dim=1).values[0]   # 沿序列取最大值
    idx = w.nonzero().squeeze(-1).tolist()
    vec = {tok.convert_ids_to_tokens(i): w[i].item() for i in idx}
    if top:                                               # 可再裁剪，只留權重最高的幾個詞
        vec = dict(sorted(vec.items(), key=lambda kv: -kv[1])[:top])
    return vec

DOCS = [
    "PT-205 pitch motor brake fault: check brake coil supply and air gap; replace brake set if out of range.",
    "PT-203 pitch motor overtemperature: stop, cool down, check cooling fan and filter before reset.",
    "PT-230 pitch backup power test failed: check backup battery voltage and charging circuit.",
    "GB-117 gearbox high-speed shaft bearing temperature high: check oil level and vibration trend.",
]

# 建索引：倒排索引 詞 -> [(文件編號, 權重)]
inverted = {}
for doc_id, text in enumerate(DOCS):
    for term, weight in encode(text).items():
        inverted.setdefault(term, []).append((doc_id, weight))

def search(query, k=3):
    scores = {}
    q = encode(query)
    for term, qw in q.items():                            # 只翻查「查詢裡有的詞」
        for doc_id, dw in inverted.get(term, []):
            scores[doc_id] = scores.get(doc_id, 0.0) + qw * dw  # 內積
    return sorted(scores.items(), key=lambda kv: -kv[1])[:k], q

hits, q = search("blade will not turn")       # 口語問法
for doc_id, score in hits:
    print(round(score, 2), DOCS[doc_id])
print(sorted(q.items(), key=lambda kv: -kv[1])[:10])    # 看看模型替查詢加了哪些擴展詞

最後一行是 SPLADE 的優點：能直接把查詢展開後的詞印出來檢視。實務上通常不自己寫倒排索引，而是交給支援稀疏向量的搜尋引擎或向量資料庫；上線前要用自己的評估集（第 021 堂）比較它和 BM25、稠密向量的差異，不要預設一定更好。

⚠️ SPLADE 常見的坑 / 何時不該用

  • 語言與領域不符：模型在什麼語料訓練，就擅長什麼。拿英文模型查中文手冊，或拿通用模型查大量專有代碼，效果可能不如 BM25；要選對語言的模型，並用自己的資料評估。
  • 擴展詞帶進雜訊：「煞車」可能同時擴展出不相關的設備。要檢視展開結果，必要時裁剪低權重的詞。
  • 索引比 BM25 大、查詢更慢：每段文字的非零詞比原詞多，查詢端也會展開多個詞；稀疏正則與裁剪就是在調這個平衡。
  • 代碼與料號被稀釋：PT-203 這類精確字串被切成子詞，擴展可能讓它和 PT-230 靠得更近。精確代碼的查詢，仍建議同時保留 BM25 或做混合檢索（第 004 堂）。
  • 文件更新要重新編碼：模型換版或文件改動，都要重新跑模型建索引，成本比 BM25 高。
  • 不要拿它取代評估：是否比 BM25 或稠密向量好，取決於你的資料。用第 021 堂的方法建評估集再決定。
  • 不適合的場景：語料很小、關鍵字都很固定，或沒有資源維護模型與重編碼流程時，BM25 加稠密向量的混合通常已足夠。
風場、機型、手冊內容與數據皆為虛構，實際作業以原廠手冊與現場規範為準。互動範例的擴展表是手寫的簡化模擬，不代表真實模型的輸出。

📝 小測驗

SPLADE 的輸出為什麼能放進倒排索引？

SPLADE 的向量維度就是詞表大小，非零的才是有意義的詞；稀疏正則讓非零很少，就能像 BM25 一樣用倒排索引。

技師問「葉片轉不動」，手冊寫「角度卡住、煞車異常」。SPLADE 比 BM25 容易命中，主要靠什麼？

學習式的詞彙擴展讓查詢與文件在詞表上有交集，這是它解決詞彙不匹配的方式；代價是索引變大與可能帶進雜訊。
