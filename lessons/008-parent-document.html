第 008 堂進階約 12 分鐘

父子文件檢索：用小塊命中，回傳整節大塊

切塊大小是兩難：塊切小，向量語意集中、命中精準，卻常缺少前後文（少了安全措施、少了復歸步驟）；塊切大，內容完整，向量卻被一整節的雜訊稀釋，反而不容易命中。父子文件檢索（Parent-Document / Small-to-Big）把兩者拆開：用「小塊」建索引負責找，命中後回傳它所屬的「父段落」負責讀。

🎬 動畫：小塊命中「安裝」，回傳整節《旋角馬達更換程序》

🧩 重點整理

檢索單位 ≠ 閱讀單位小塊向量語意集中、好命中；大塊內容完整、好理解。父子檢索讓「拿去比對的」和「交給 LLM 的」使用不同大小的塊。
兩個儲存區向量索引只存小塊（子）與父 ID；文件庫（docstore）以父 ID 存整節原文。命中後用 ID 查表，不必再做一次向量檢索。
常見實作LangChain 的 ParentDocumentRetriever 以 child_splitter 切子塊；未設 parent_splitter 時，父就是原始整份文件。LlamaIndex 的 auto-merging retriever 預設建立 2048／512／128 token 三層。
自動合併更省LlamaIndex 版本的做法是：同一個父節點底下被命中的子塊夠多（超過門檻）才換成父節點，只命中零星一兩塊就維持原樣，避免把整節塞進上下文。

🧪 互動範例：小塊直接回傳 vs. 回傳父段落 vs. 整節直接檢索

下面是《OW-8 運維手冊》5 個章節、共 22 個小塊（虛構）。選一個技師的問題，切換三種做法：小塊直接回傳、小塊命中→回傳父段落、整節當一塊檢索。拉動「檢索單位數」看看結果的變化；「關鍵句」是回答這題必須看到的小塊。下方統計會告訴你：涵蓋了幾個關鍵句、回傳多少字、關鍵句占多少比例。檢索使用簡化的 TF-IDF 模擬，不是真正的嵌入模型。

💻 程式範例（Python）

手動實作父子檢索：先把每一節切成小塊並記下父 ID，只對小塊做嵌入；查詢時找出最相近的小塊，依父 ID 從字典（相當於 docstore）取回整節，依排名去重後交給 claude-sonnet-5 回答。範例文件為虛構。

import numpy as np
from sentence_transformers import SentenceTransformer
import anthropic

# ① 原始文件：以「節」為父段落（虛構的 OW-8 手冊）
sections = {
    "sec-6.3": [
        "適用範圍：OW-8 旋角馬達更換，備品料號 PT-MTR-02，須開立工單。",
        "安全前置：完成上鎖掛牌（LOTO），鎖定葉片並隔離驅動器電源。",
        "拆卸：標示並拆下電源線與編碼器線，以吊具支撐後抽出馬達。",
        "安裝：清潔接合面，依原廠扭力表分次對角鎖緊固定螺栓。",
        "復歸測試：解除掛牌後低速手動旋角，確認回授與煞車正常再記錄。",
    ],
    "sec-7.2": ["適用範圍：OW-8 偏航馬達更換……", "安裝：依原廠扭力表鎖緊固定螺栓……"],
}

# ② 索引階段：只對「小塊」嵌入，並記住父 ID；整節原文放進 docstore
embedder = SentenceTransformer("BAAI/bge-m3")
docstore = {pid: "\n".join(kids) for pid, kids in sections.items()}
children = [(pid, kid) for pid, kids in sections.items() for kid in kids]
child_vecs = embedder.encode([k for _, k in children], normalize_embeddings=True)

# ③ 檢索：找最相近的小塊，依父 ID 取回整節（依排名去重）
def retrieve_parents(question, top_n=3):
    q = embedder.encode([question], normalize_embeddings=True)[0]
    order = np.argsort(-(child_vecs @ q))[:top_n]
    parent_ids = list(dict.fromkeys(children[i][0] for i in order))
    return [(pid, docstore[pid]) for pid in parent_ids]

# ④ 生成：把父段落放進 prompt，並附上出處
client = anthropic.Anthropic()
def answer(question):
    context = "\n\n".join(f"[{pid}]\n{text}" for pid, text in retrieve_parents(question, top_n=3))
    prompt = f"參考資料：\n{context}\n\n問題：{question}\n請只依參考資料回答，並標明出處；資料中沒有就說不知道。"
    msg = client.messages.create(model="claude-sonnet-5", max_tokens=512,
                                 messages=[{"role": "user", "content": prompt}])
    return msg.content[0].text

print(answer("新的旋角馬達怎麼裝回去？"))

⚖️ 四種做法比較

大塊直接檢索小塊直接檢索（第 002 堂）父子檢索（本堂）重排序（第 005 堂）
索引與回傳索引與回傳同一種大塊索引與回傳同一種小塊索引小塊、回傳父段落不改塊大小，重排候選
解決什麼內容完整命中精準命中精準又內容完整候選排序不夠準
額外成本無無多一個 docstore；LLM 讀入的字數變多多一次 cross-encoder 運算
主要風險向量被稀釋，難命中缺前後文，答案不完整父段落夾帶不相關內容，稀釋 LLM 注意力不能找回漏掉的段落

⚠️ 父子檢索常見的坑 / 何時不該用

  • 父段落太大反而有害：問題只需要一個料號，卻回傳整節數千字，會增加成本與雜訊。父塊要對齊「有意義的完整單位」（一個程序、一個告警），而不是越大越好。
  • 多個小塊命中同一父段落要去重：否則同一節被重複塞進 prompt。範例程式用 dict.fromkeys 依排名去重；LlamaIndex 則用門檻決定是否合併。
  • 小塊也要能單獨看懂：若小塊只寫「依上節步驟拆下馬達」，向量本身缺少語意，父子檢索也救不了；下一堂的情境化檢索會處理這個問題。
  • 跨父段落的問題仍要多路召回：「旋角與偏航馬達更換有何不同」需要兩節內容，Top-N 要夠大，或搭配第 006 堂的多重查詢。
  • 短文件、精確查詢不需要：文件本來就短、或使用者直接查料號 PT-MTR-02 時，小塊命中就已足夠，多一層 docstore 只是增加複雜度。
範例中的鷗灣離岸風場、OW-8 機型、運維手冊內容、章節編號、料號與告警代碼皆為虛構，僅供教學示範；互動範例使用簡化的 TF-IDF 模擬，非真實嵌入模型；實際作業以原廠手冊與現場規範為準。

📝 小測驗

父子文件檢索為什麼要「用小塊建索引、回傳大塊」？

小塊與大塊各有優缺點：小塊利於「找」，大塊利於「讀」。父子檢索把兩件事拆開，各取所長。它不會省去向量計算，也和重排序解決的是不同問題，兩者可以搭配。

技師只想查「備品料號 PT-MTR-02 是什麼」，但父段落是 5 個小塊的整節程序，此時最合理的做法是？

父子檢索的代價是回傳內容變多。問題只需單一事實時，小塊就夠；LlamaIndex 的自動合併就是靠「同一父節點命中夠多子塊才合併」的門檻來避免不必要的展開。
