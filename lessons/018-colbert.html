第 018 堂高階約 18 分鐘

ColBERT 延遲互動：逐詞向量比對

技師查「PT-205 煞車間隙」，一般的向量檢索把整段手冊壓成一個向量，「PT-205」與「PT-203」這種只差一個數字的段落，向量會非常接近，關鍵細節被平均掉了。ColBERT 改成每個詞保留一個向量，查詢時讓每個查詢詞各自去找文件裡最相似的詞（MaxSim）再加總，比對更精細，而文件的詞向量仍可事先算好。這種「分開編碼、最後才互動」的做法叫延遲互動（late interaction）。

🎬 動畫：從單一向量到逐詞 MaxSim

🧩 重點整理

每個詞一個向量ColBERT（Khattab 與 Zaharia，SIGIR 2020）用 BERT 為查詢與文件的每個 token 各產生一個向量，不像一般 bi-encoder 壓成單一向量。
MaxSim 加總分數 = 對每個查詢 token，取它與所有文件 token 相似度的最大值，再全部相加。每個查詢詞都有人「認領」，分數才高。
延遲互動查詢與文件分開編碼，文件向量可離線預算；相互比對留到最後一步，比 cross-encoder 把兩者串在一起逐對重算便宜。
代價是儲存每份文件要存「詞數 × 維度」個數字。ColBERTv2（2022）用殘差壓縮縮小索引，PLAID 則加快檢索，但仍比單一向量大、也複雜。

🧪 互動範例：單一向量 vs 逐詞 MaxSim

下面是虛構的《OW-8 運維手冊》8 個片段。這裡的詞向量不是訓練出來的模型，只是把每個詞的字元（單字與相鄰兩字）雜湊成 128 維向量，所以字面相近的詞向量也相近（例如 205 與 203）。單一向量是把詞向量平均後算餘弦；ColBERT 模式則真的在瀏覽器裡對每個查詢詞取 MaxSim 再加總。預設的 4 個查詢中，前 3 個（代碼加關鍵詞、單獨的料號）單一向量會把目標排到第 2 或第 3 名，ColBERT 模式排第 1；第 4 個兩種方式都答對，不是每個查詢都會有差別。真實的 ColBERT 詞向量帶有上下文語意，這裡只讓你看「逐詞比對」的機制。

💻 程式範例（Python）

先用 NumPy 寫出 MaxSim 的核心，看懂分數怎麼來；再用 RAGatouille 套件載入 ColBERT 模型建索引與檢索（pip install ragatouille anthropic numpy），最後交給 claude-sonnet-5 回答。文件與問題皆為虛構。colbert-ir/colbertv2.0 主要以英文訓練，若手冊是繁體中文，請換成支援中文的多語言延遲互動模型。

import numpy as np, anthropic
from ragatouille import RAGPretrainedModel

# 1) MaxSim 核心：q 為 (查詢詞數, 維度)，d 為 (文件詞數, 維度)，皆已 L2 正規化
def maxsim(q, d):
    sim = q @ d.T                      # 查詢詞 × 文件詞 的餘弦相似度表
    return sim.max(axis=1).sum()      # 每個查詢詞取最大，再加總

# 2) 手冊片段（虛構）
docs = [
    "PT-205 旋角馬達煞車異常：檢查煞車線圈電阻與煞車間隙，確認釋放時無拖滯。",
    "PT-203 旋角馬達過溫：檢查冷卻風扇與風道，量測感測器阻值。",
    "PT-MTR-02 旋角馬達備品，適用 OW-8，庫存位置為港區倉庫。",
]

# 3) 載入 ColBERT 模型並建索引（文件的詞向量在這一步算好存起來）
rag = RAGPretrainedModel.from_pretrained("colbert-ir/colbertv2.0")  # 中文請換多語言模型
rag.index(collection=docs, index_name="ow8_manual", split_documents=False)

# 4) 檢索：查詢只需編碼一次，再對候選文件算 MaxSim
question = "PT-205 煞車間隙怎麼檢查"
hits = rag.search(question, k=2)
context = "\n".join(h["content"] for h in hits)

# 5) 生成答案
client = anthropic.Anthropic()
msg = client.messages.create(
    model="claude-sonnet-5", max_tokens=500,
    messages=[{"role": "user", "content":
        f"只根據下列手冊片段回答，沒寫到就說不知道。\n{context}\n\n問題：{question}"}])
print(msg.content[0].text)

注意：套件的參數與預設值會隨版本調整，請以官方文件為準。正式使用時，文件要先切塊（第 002 堂），因為 ColBERT 對每份文件有最大長度；並記得把索引大小與查詢延遲納入評估。

ColBERT 介於 bi-encoder 與 cross-encoder 之間：比單一向量細，又比 cross-encoder 便宜，因為文件端可以預先算好。它常被用來當第一階段檢索，也可以當作重排序器使用。

⚠️ ColBERT 常見的坑 / 何時不該用

  • 索引很大：每個詞一個向量，儲存量約隨總詞數成長。語料大時要評估壓縮（ColBERTv2）與專用索引（PLAID）。
  • 語言與領域要對：預訓練模型主要以英文訓練，繁體中文手冊與「PT-205」這類專有代碼要選對模型，並用自己的資料驗證。
  • 不是所有專有詞都會精確命中：詞向量是學出來的，罕見代碼不一定被當成「完全相同」。需要保證精確比對時，仍要搭配 BM25（第 004 堂）。
  • 文件有長度上限：過長要先切塊；切塊策略仍會影響結果。
  • 實作與維運較複雜：不像單一向量能直接放進一般向量資料庫；選工具時要確認是否支援多向量（multi-vector）。
  • 小語料不划算：語料不大、查詢多半語意型時，向量檢索加重排序更簡單，先量測效果再決定要不要上。
風場、機型、手冊內容與數據皆為虛構，實際作業以原廠手冊與現場規範為準。互動範例的詞向量是字元雜湊的玩具模型，動畫中的相似度數值僅為示意，告警代碼與料號僅供教學示範。

延伸閱讀：Khattab 與 Zaharia，〈ColBERT: Efficient and Effective Passage Search via Contextualized Late Interaction over BERT〉（SIGIR 2020，arXiv:2004.12832）；Santhanam 等，〈ColBERTv2: Effective and Efficient Retrieval via Lightweight Late Interaction〉（NAACL 2022，arXiv:2112.01488）；Santhanam 等，〈PLAID: An Efficient Engine for Late Interaction Retrieval〉（CIKM 2022，arXiv:2205.09707）。

📝 小測驗

ColBERT 的 MaxSim 分數怎麼算？

A 是單一向量的做法，C 是 cross-encoder。ColBERT 逐個查詢詞找最像的文件詞（max），再加總（sum）。

為什麼叫「延遲互動」，而且比 cross-encoder 便宜？

cross-encoder 每個查詢都要和每份候選文件一起重新計算；ColBERT 的文件詞向量事先算好，查詢時只編碼查詢，再做輕量的 MaxSim。
