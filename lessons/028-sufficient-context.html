第 028 堂進階約 20 分鐘

充分上下文與拒答：檢索到的內容，夠回答嗎？

RAG 出錯，不一定是模型亂講，常常是檢索到的片段根本不夠回答，模型卻照樣給了答案。充分上下文（Sufficient Context）把「相關」和「充分」分開：先判斷這些片段光靠自己能不能明確回答問題，不夠就補檢索，補不到就拒答（abstain）並說明缺什麼，而不是硬湊一個像樣的答案。

🎬 動畫：相關，不代表夠用

🧩 重點整理

相關 ≠ 充分片段和問題談同一件事叫相關；光靠片段就能明確回答才叫充分。同告警、不同機型、缺數值的片段，都是相關但不充分。
拆成「需要的資訊」逐項查問題需要告警代碼、機型、步驟、門檻值等；逐項在片段裡找證據，缺哪一項就說缺哪一項，比籠統的「不確定」更有用。
三條出路充分就回答並附引用；不充分但可補救，就改寫查詢、換資料源再檢索；補不到就拒答，說明缺什麼，並指引下一步。
答或不答是取捨拒答越多、答出來的越準，但覆蓋率越低。研究也發現不充分時模型偶爾仍答得對，所以門檻要用自己的評估集調，不是一刀切。

🧪 互動範例：有沒有充分性檢查，差在哪？

下面有 12 段《OW-8 運維手冊》片段（虛構）。選一個問題，系統用 BM25 取回前 k 段，再檢查「回答這題需要的資訊」是否都出現在片段裡（代碼、機型、步驟、數值等）。你可以切換成「一律回答」，看看沒有把關時會發生什麼；把 k 調小（3 以下）則會看到「更換旋角馬達前的安全步驟」因取回不全被誤拒，k＝5 才答得出來。

這是簡化模擬：真實系統用 LLM 判斷器，這裡改用每題預設的「必要資訊」清單比對文字；自行輸入的問題只檢查其中的代碼與機型（例如 OW-6、WTG-17）是否出現在片段裡。

💻 程式範例（Python）

最小的「充分性檢查＋拒答」實作：取回片段後先請模型判斷「夠不夠回答」，不夠就回報缺少的資訊，夠才進入生成。需要 anthropic 套件與 API 金鑰；retrieve 為教學用替身，文件與問題皆為虛構。

import json
from anthropic import Anthropic

client = Anthropic()            # 需要環境變數 ANTHROPIC_API_KEY
MODEL = "claude-sonnet-5"

DOCS = [
    "PT-230 旋角備援電源測試失敗：檢查備援電池電壓與充電迴路，必要時更換電池模組。",
    "PT-203 旋角馬達過溫：先停機降溫，檢查冷卻風扇與濾網，復歸前確認繞組溫度。",
    "OW-8 YW-042 偏航誤差過大：檢查風向計校正與偏航驅動器狀態。",
    "上鎖掛牌 LOTO：作業前切斷並上鎖所有能量來源，驗證零能量後才可開始。",
]

def retrieve(query, k=3):       # 教學用替身：依共同字元數排序；實務請換成前面課程的檢索
    return sorted(DOCS, key=lambda t: len(set(query) & set(t)), reverse=True)[:k]

def ask(system, user):
    msg = client.messages.create(model=MODEL, max_tokens=600, system=system,
                                 messages=[{"role": "user", "content": user}])
    return msg.content[0].text

JUDGE = """你是檢索品質把關員。只依「片段」判斷，不可用自己的知識補充。
先想：這個問題需要哪些資訊才能明確回答？片段是否都有？
只輸出 JSON：{"sufficient": true 或 false, "missing": ["缺少的資訊"]}"""

def check_sufficiency(question, passages):
    raw = ask(JUDGE, f"問題：{question}\n片段：\n" + "\n".join(passages))
    try:
        return json.loads(raw)
    except json.JSONDecodeError:    # 判斷器沒照格式輸出：保守處理，視為不充分
        return {"sufficient": False, "missing": ["（判斷器輸出無法解析）"]}

def answer(question):
    passages = retrieve(question)
    verdict = check_sufficiency(question, passages)
    if not verdict["sufficient"]:
        missing = "、".join(verdict["missing"])
        return f"手冊未載明，無法回答。缺少：{missing}。請查原廠文件或聯絡工程師。"
    return ask("只根據片段回答，並指出依據哪一則片段。",
               f"問題：{question}\n片段：\n" + "\n".join(passages))

print(answer("PT-230 備援電池電壓低於多少要更換？"))   # 片段沒有數值 → 預期拒答
print(answer("PT-203 旋角馬達過溫怎麼處理？"))           # 片段足夠 → 預期回答

注意：判斷器的提示要明確要求「只依片段判斷」，否則模型會用自己的知識補上缺的部分，等於把問題藏起來。實務上可把判斷結果與缺少的資訊記入日誌，方便找出手冊該補哪些內容；也可以只對高風險問題（作業安全、復歸條件）啟用，以控制成本與延遲。

⚠️ 充分上下文常見的坑 / 何時不該用

  • 把相關分數當充分：檢索分數高只代表像，不代表夠用。同告警不同機型、缺關鍵數值的片段，分數都可能很高。
  • 判斷器偷用自己的知識：若提示沒要求「只依片段」，判斷器會憑常識認定「夠了」，把缺口蓋掉。提示要明確，並用抽樣檢查。
  • 一律拒答的過度保守：不充分時模型有時仍答得對，門檻太嚴會讓技師常得到「無法回答」。要看覆蓋率，不只看正確率。
  • 拒答沒有下一步：只說「無法回答」會讓人卡住。要列出缺什麼、建議查哪份文件或聯絡誰。
  • k 太小造成誤拒：答案分散在多份文件（例如步驟在一處、安全注意事項在另一處）時，取回太少會被判不充分；先確認檢索夠完整，再調門檻。
  • 判斷結果沒被利用：把「缺少的資訊」記下來，就知道手冊或知識庫該補什麼。只拿來攔截而不回饋，等於浪費訊號。
  • 不適合的場景：閒聊或創意型問答、答案本身一眼可驗證，或延遲極敏感的場景，多一次判斷的成本不一定划算；但涉及作業安全的問題值得開啟。
風場、機型、手冊內容與數據皆為虛構，實際作業以原廠手冊與現場規範為準。互動範例的「必要資訊」比對是簡化模擬，不代表真實判斷器的行為。

📝 小測驗

取回的片段與問題「談同一個告警」，為什麼仍可能不充分？

相關是「談同一件事」，充分是「光靠這些片段就能明確回答」。少了機型、數值或步驟，再相關也不夠。

充分性判斷器發現片段不夠時，最合理的處置是？

不充分時硬答是風險所在。可補救就補救，補不到要誠實拒答並指出缺口，讓技師知道該去查什麼。
