第 038 堂高階約 15 分鐘

FLARE 主動式檢索：沒把握的時候才去查

請模型寫一份 PT-203 的處置報告，開頭用題目檢索一次，寫到後面的細節（門檻、動作、次數）開頭根本沒查到，只能猜。每一句都檢索又太貴。FLARE（Forward-Looking Active REtrieval）的做法是：先暫寫下一句，看每個詞的生成機率；只要有詞低於門檻，才用這句去檢索並重寫。模型沒把握時才查。

🎬 動畫：先暫寫，沒把握再檢索

🧩 重點整理

長文生成需要「邊寫邊查」要用到的資訊會隨內容展開才浮現。只在開頭檢索一次，後面的細節常常沒有依據。
用信心決定何時檢索先暫寫下一句；任何詞的機率低於門檻 θ，就檢索並重寫，否則直接採用。省下不必要的檢索。
查詢來自暫寫句用暫寫句當查詢，並把低信心詞遮掉，避免錯誤的詞把檢索帶偏。論文另有先生成明確問句的作法。
需要可靠的詞機率許多模型 API 不提供，信心也不等於正確。θ 要用評估集調，並留意延遲與成本。

🧪 互動範例：不檢索、每句都檢索、FLARE

下面是一份虛構的 PT-203 處置報告，共 6 句。每句的暫寫版本與各詞機率是預先寫好的示意（真實系統來自模型的詞機率）。檢索是瀏覽器內真的在算（BM25，中文用二字詞），知識庫是 6 條虛構的《OW-8 運維手冊》句子。拖動門檻 θ，看 FLARE 在哪幾句觸發檢索、花了幾次檢索、還剩幾句錯誤。

💻 程式範例（Python）

下面是 FLARE 迴圈的最小實作。draft_with_probs 代表「能回傳每個詞機率的模型」（例如自架的開源模型），這是 FLARE 的前提；檢索到文件後，用 claude-sonnet-5 重寫該句。範例以空白斷詞，中文實務上請換成適合的斷詞器。

import anthropic
from rank_bm25 import BM25Okapi

client = anthropic.Anthropic()
DOCS = [
    "PT-203 在旋角馬達繞組溫度超過 95°C 時發出。",
    "PT-203 首次出現時，系統自動降載。",
    "PT-203 連續復歸 3 次須通報遠端監控中心並派員。",
]
bm25 = BM25Okapi([d.split() for d in DOCS])
THETA = 0.4

def draft_with_probs(question, written):
    """回傳 [(詞, 機率), ...]：用能取得詞機率的模型暫寫下一句（此處省略實作）。"""
    raise NotImplementedError

def retrieve(query, k=2):
    scores = bm25.get_scores(query.split())
    best = sorted(range(len(DOCS)), key=lambda i: -scores[i])[:k]
    return [DOCS[i] for i in best]

def flare(question, max_sentences=6):
    written = ""
    for _ in range(max_sentences):
        tokens = draft_with_probs(question, written)       # 前瞻：暫寫下一句
        sentence = "".join(w for w, _ in tokens)
        if min(p for _, p in tokens) < THETA:           # 有詞沒把握
            masked = " ".join(w for w, p in tokens if p >= THETA)  # 遮掉低信心詞
            docs = retrieve(masked)
            msg = client.messages.create(model="claude-sonnet-5", max_tokens=300,
                messages=[{"role": "user", "content":
                    "依據下列資料，重寫這一句，不得加入資料沒有的事實。\n資料：\n" + "\n".join(docs)
                    + "\n暫寫句：" + sentence}])
            sentence = msg.content[0].text
        written += sentence                                     # 採用並接到答案後面
    return written

實務上要記錄每次是否觸發檢索，並用評估集（第 021 堂）比較「一次性檢索」與 FLARE 的答案正確性、檢索次數與延遲，再決定 θ。

⚠️ FLARE 常見的坑 / 何時不該用

  • 拿不到詞機率：許多託管模型 API 不回傳詞機率，FLARE 就無從判斷。此時改用其他訊號（如自我反思，第 013 堂），或在自架模型上實作。
  • 信心不等於正確：模型可能很有把握地寫錯，這種句子不會觸發檢索；低機率也可能只是措辭多樣。
  • θ 要調：太高等於每句都檢索，太低會漏掉猜錯的句子。用評估集掃過一輪，不要照搬任何數字。
  • 延遲與成本：觸發時要暫寫、檢索、再重寫，比一次性檢索慢；短答案或單一事實問題不值得。
  • 查詢品質：暫寫句若整句都是猜的，遮掉後可能剩不下幾個詞，查詢過短，檢索會失準。
  • 安全相關數值：門檻值、次數這類內容，建議重寫後仍要求引用出處（第 025 堂），並由人覆核。
風場、機型、手冊內容、告警代碼與數據皆為虛構，實際作業以原廠手冊與現場規範為準。互動範例的詞機率是預先寫好的示意，不是真實的模型輸出。

延伸閱讀：Jiang 等人，Active Retrieval Augmented Generation（arXiv 2305.06983，EMNLP 2023）。

📝 小測驗

FLARE 在什麼情況下才會觸發檢索？

FLARE 用模型對暫寫句的信心決定：有詞低於門檻才檢索並重寫，否則直接採用。

下列哪一種情況最不適合用 FLARE？

FLARE 依賴詞機率，且為長文生成設計；拿不到機率、問題又很短時，用一般檢索即可。
