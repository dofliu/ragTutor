RAG-Fusion：多查詢 + 倒數排名融合

技師隨口一句「葉片轉不動」，字面上最像的是「葉片卡滯排查」，真正要查的「PT-203 旋角馬達過溫」卻排在第 6 名。上一堂的 Multi-Query 把多個問法的結果聯集起來，但聯集沒有統一的排序。RAG-Fusion 同樣先讓 LLM 把問題改寫成多個問法、各自檢索，再用倒數排名融合（Reciprocal Rank Fusion, RRF）把多份排名合併成一份：被越多問法排在前面的段落，名次越高。

🎬 動畫：一個問題、多個問法、一份融合後的排名

🧩 重點整理

一個問法不夠技師的口語問句常和手冊用詞對不上。讓 LLM 把問題改寫成多個角度的問法（口語、維修用語、告警代碼），涵蓋面比單一查詢大。
融合的是「名次」RRF 對每份清單只看名次：score(d) = Σ 1/(k+rank)。不同檢索器、不同問法的原始分數尺度不一，換成名次就能直接相加；常見預設 k = 60，出自 RRF 原論文。
比聯集多了排序上一堂 Multi-Query 只做去重聯集，各問法的結果之間沒有統一排序。RAG-Fusion 多出的就是這一步：讓被多個問法認同的段落自然上浮。
有代價，也有風險每次提問多一輪 LLM 改寫、多次檢索。Rackauckas 的論文也指出，產生的問法若和原問題不夠相關，答案會偏題。

🧪 互動範例：一個問法 vs. 多問法 RRF 融合

下面是虛構的《OW-8 運維手冊》8 個段落。原問題是「葉片轉不動」，正解是「PT-203 旋角馬達過溫」。勾選要使用的問法（第 4 個是故意偏離原意的問法，預設不勾），再切換合併方式：只用原問題、聯集（依問法順序列出、去重，沒有統一排序）、或 RRF 融合。可以拖動 k 看名次差距如何被壓平。檢索用簡化的 TF-IDF 餘弦相似度模擬，不是真正的嵌入模型。

💻 程式範例（Python）

手動實作 RAG-Fusion：用 claude-sonnet-5 把問題改寫成多個問法（連同原問題），每個問法用向量檢索取前幾名，再用 RRF 融合成一份排名。範例文件為虛構。

import numpy as np
from sentence_transformers import SentenceTransformer
import anthropic

client = anthropic.Anthropic()
embedder = SentenceTransformer("BAAI/bge-m3")

# ① 知識庫：虛構的 OW-8 手冊段落
chunks = [
    "PT-203 旋角馬達過溫：繞組溫度超過門檻時控制器會限制電流並跳脫，請先檢查散熱風道、冷卻風扇與感測器接線。",
    "旋角馬達跳脫後的復歸：確認原因排除後，於機艙控制面板解除跳脫，並手動試轉葉片。",
    "葉片轉不動的初步排查：先確認旋角軸承潤滑與減速機有無異物卡阻，再檢查驅動器輸出。",
    # ……
]
vecs = embedder.encode(chunks, normalize_embeddings=True)

# ② 讓 LLM 把問題改寫成多個問法
def make_queries(question, n=3):
    msg = client.messages.create(
        model="claude-sonnet-5", max_tokens=200,
        messages=[{"role": "user", "content":
            f"你在協助檢索風機運維手冊。請針對下面的問題，產生 {n} 個不同角度的搜尋問法"
            "（例如維修用語、可能的告警代碼），每行一個，不要編號、不要多餘說明。\n"
            f"問題：{question}"}])
    variants = [l.strip() for l in msg.content[0].text.splitlines() if l.strip()]
    return [question] + variants[:n]        # 原問題也保留

# ③ 每個問法各自檢索，得到一份名次清單
def retrieve(query, k=20):
    q = embedder.encode([query], normalize_embeddings=True)[0]
    return [int(i) for i in np.argsort(-(vecs @ q))[:k]]

# ④ RRF：score(d) = Σ 1 / (k + rank)
def rrf(rankings, k=60):
    score = {}
    for ranking in rankings:
        for rank, i in enumerate(ranking, start=1):
            score[i] = score.get(i, 0) + 1 / (k + rank)
    return sorted(score, key=score.get, reverse=True)

question = "葉片轉不動"
queries = make_queries(question)
for i in rrf([retrieve(q) for q in queries])[:3]:
    print(chunks[i], "\n---")

⚖️ 五種做法比較

一般檢索（第 001 堂）混合檢索（第 004 堂）Multi-Query（第 006 堂）RAG-Fusion（本堂）
用幾個查詢1 個1 個（兩種檢索器）多個問法多個問法（含原問題）
怎麼合併不用合併RRF 合併兩路排名去重聯集RRF 合併所有問法的排名
額外成本無多維護一份 BM25 索引一次 LLM 改寫 + 多次檢索同 Multi-Query；融合本身幾乎免費
主要風險口語問法對不上手冊用詞兩路都沒看到的詞仍找不到聯集沒有排序，雜訊一起進來問法偏離原意會拉進離題段落

兩者可以疊加：每個問法各自跑混合檢索（BM25 + 向量），把所有排名一次丟進 RRF；融合後再接重排序（第 005 堂）。

⚠️ RAG-Fusion 常見的坑 / 何時不該用

  • 問法偏離原意：LLM 可能把「葉片轉不動」擴寫成「偏航馬達過溫」。互動範例勾選第 4 個問法就能看到：離題段落被拉進前幾名。提示詞要求問法「忠於原問題」，並限制問法數量（常見 3～4 個）。
  • RRF 不看相關程度：融合只用名次，不知道某段落其實很不相關。某個問法在整份知識庫都沒有好答案時，它的第 1 名也照樣拿到最高的單路分數。需要精準時，融合後再加重排序。
  • 延遲與成本：多一次 LLM 呼叫，檢索次數乘上問法數。查詢量大或要求即時回應時要先估算；可平行發出各問法的檢索來壓低延遲。
  • 問題本身已很精確就不必做：像直接輸入「PT-203」這種明確的告警代碼，單一查詢（或混合檢索）通常已經夠用，多問法只是額外花費。
  • 每份清單要夠長：只取前 3 名就融合，名次資訊太少；通常每個問法取前 10～20 名再融合，最後才截取 Top-k。
  • 評估要用自己的資料：公開文獻多為人工評估或特定資料集，效果因知識庫而異；換成自己的語料請用評估集量測，而不是假設一定變好。
範例中的鷗灣離岸風場、OW-8 機型、運維手冊內容、告警代碼與各數值皆為虛構，僅供教學示範；互動範例使用簡化的 TF-IDF 模擬，問法為人工預寫；實際作業以原廠手冊與現場規範為準。

📝 小測驗

RAG-Fusion 和第 006 堂的 Multi-Query（聯集）最主要的差別是什麼？

兩者都會讓 LLM 產生多個問法並各自檢索；差別在合併方式。聯集只去重，各問法的結果之間沒有統一排序；RRF 把名次換成分數相加，被多個問法排在前面的段落總分最高。

RRF 為什麼只用「名次」而不直接把各路的分數相加？

向量相似度、BM25 分數、不同問法的分數範圍都不一樣，直接相加沒有意義。RRF 只取每份清單的名次，用 1/(k+rank) 換算後相加，因此能合併任意來源的排名。代價是它不知道「第 1 名到底有多相關」。
