第 033 堂進階約 15 分鐘

MMR 多樣性重排：前 k 名不要全是同一件事

技師問「PT-203 旋角馬達過溫怎麼處理」，前 4 名卻是手冊、技術通報、工單與舊款手冊，全都在講清潔散熱，負載、感測器、安全步驟一個也沒進來。相關性排序替每一段各自打分，不看彼此重複。MMR（Maximal Marginal Relevance，最大邊際相關）在每一步挑片段時，同時考慮「跟問題像不像」與「跟已經選的像不像」，用同樣的 k 個名額涵蓋更多角度。

🎬 動畫：讓名額留給新的角度

🧩 重點整理

相關不等於有用知識庫裡同一件事常有手冊、通報、工單與新舊版本。每段都「很像問題」，前 k 名就被重複內容佔滿，浪費 context window。
MMR 的取捨每輪選出「λ × 與問題的相似度 − (1 − λ) × 與已選片段的最大相似度」最高的一段。已選什麼會改變候選的分數，這是它與一般排序的差別。
λ 是旋鈕λ = 1 等於原本的相關性排序，λ = 0 只求不重複。實務上從居中的值開始，用自己的問題集與評估指標調整。
多樣不等於正確λ 太小會混進不相關的段落；多來源佐證的訊息也可能被去重。MMR 是在候選池上的重排，不取代檢索品質與評估。

🧪 互動範例：同一批候選，用與不用 MMR

知識庫是 19 段虛構的《OW-8 運維手冊》與相關文件，其中有不少幾乎重複的內容（手冊、技術通報、工單講同一件事）。系統先用 TF-IDF 餘弦相似度取前 fetch_k 段當候選池，再選出 k 段。上排是「不用 MMR」的前 k 名，下排是「用 MMR」的結果。拉動 λ，看涵蓋的面向與重複程度怎麼變。

每段右上標示它屬於哪個面向（事先標好）；「涵蓋面向」只計入這個問題需要的面向。相似度用瀏覽器內的詞袋向量，只是示意，真實系統請用嵌入模型。

λ（相關性 ↔ 多樣性）：
k（要選幾段）： fetch_k（候選池）：
不用 MMR：前 k 名
用 MMR 選出的 k 段

💻 程式範例（Python）

下面用 numpy 實作 MMR：輸入問題向量與候選向量（已正規化），每輪選出分數最高的一段。向量由 embed 產生，這裡以 sentence-transformers 為例；生成答案時用 anthropic 的 claude-sonnet-5。

import numpy as np
import anthropic
from sentence_transformers import SentenceTransformer

model = SentenceTransformer("BAAI/bge-m3")
client = anthropic.Anthropic()

DOCS = [
    "PT-203（OW-8）：檢查冷卻風扇與散熱片積塵並清潔。",
    "技術通報 TB-2026-017：PT-203 先清潔冷卻風扇與散熱片。",
    "工單 WO-2026-0412：PT-203，已清潔風扇與散熱片後復歸。",
    "PT-203 也可能是負載過高：檢查葉片角度調整頻率與繞組溫度趨勢。",
    "溫度感測器漂移會誤報 PT-203：比對繞組實測溫度與感測器讀值。",
    "PT-203 作業安全：進入輪轂前先順槳、鎖定葉輪並執行上鎖掛牌（LOTO）。",
]

def embed(texts):
    return model.encode(texts, normalize_embeddings=True)   # 正規化後內積即餘弦相似度

def mmr(q_vec, d_vecs, k=3, lam=0.5, fetch_k=6):
    """回傳被選中的文件索引；lam=1 等於一般相關性排序"""
    rel = d_vecs @ q_vec                                  # 與問題的相似度
    pool = list(np.argsort(-rel)[:fetch_k])               # 候選池：相關性前 fetch_k 名
    chosen = []
    while pool and len(chosen) < k:
        def score(i):
            redundancy = max((d_vecs[i] @ d_vecs[j] for j in chosen), default=0.0)
            return lam * rel[i] - (1 - lam) * redundancy
        best = max(pool, key=score)
        chosen.append(best)
        pool.remove(best)
    return chosen

query = "PT-203 旋角馬達過溫要怎麼處理？"
q_vec = embed([query])[0]
d_vecs = embed(DOCS)
picked = mmr(q_vec, d_vecs, k=3, lam=0.5)
ctx = "\n".join(DOCS[i] for i in picked)

msg = client.messages.create(
    model="claude-sonnet-5", max_tokens=400,
    messages=[{"role": "user", "content": f"只根據下列手冊段落回答。\n\n{ctx}\n\n問題：{query}"}],
)
print(msg.content[0].text)

⚠️ MMR 常見的坑 / 何時不該用

  • λ 沒調就上線：太小會混進不相關的段落，太大等於沒用。要用自己的問題集與評估指標（第 021 堂）比較。
  • 候選池太小：fetch_k 若只比 k 大一點，能挑的角度本來就少；太大又會讓低相關的段落有機會入選。
  • 把佐證當重複：手冊與技術通報都指向同一個做法，是互相印證。若需要引用來源（第 025 堂），先合併重複來源並保留出處，而不是讓 MMR 隨意丟掉。
  • 完全相同的文字：在索引階段去重比較單純，不必靠 MMR。
  • 單一事實的問題：問「PT-205 是什麼代碼」這類只需要一段答案的問題，多樣性沒有價值，λ 可以拉高。
  • 相似度看嵌入：換個說法的內容可能被視為重複，也可能把不同機型的相似段落判成重複，機型條件仍要靠中繼資料過濾（第 011 堂）。
風場、機型、手冊與工單內容及數據皆為虛構，實際作業以原廠手冊與現場規範為準。互動範例的相似度是瀏覽器內的詞袋近似，不代表真實嵌入模型的結果。

延伸閱讀：Carbonell 與 Goldstein，The Use of MMR, Diversity-Based Reranking for Reordering Documents and Producing Summaries（SIGIR 1998）；LangChain 向量庫文件中的 max_marginal_relevance_search。

📝 小測驗

MMR 每一輪挑選片段時，分數同時考慮哪兩件事？

MMR 取「λ × 與問題的相似度 − (1 − λ) × 與已選片段的最大相似度」最高者。

把 λ 設為 1，MMR 的結果會變成什麼？

λ = 1 時冗餘度那一項的權重為 0，只剩相關性；λ 越小才越偏向多樣性。
