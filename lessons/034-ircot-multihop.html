第 034 堂高階約 18 分鐘

IRCoT 多跳檢索：邊推理邊檢索，一步一步找齊證據

技師問「WO-2026-0455 換下的零件，現在還剩幾個？」答案藏在兩份文件：工單說換了哪個料號，庫存表說那個料號剩幾個。要查庫存，得先讀完工單才知道料號，這種題目叫多跳（multi-hop）。IRCoT（Interleaving Retrieval with Chain-of-Thought）讓檢索與推理輪流進行：每寫出一句推理，就拿這一句當下一次檢索的查詢，一步步把證據找齊。

🎬 動畫：先查 A，才知道要查 B

🧩 重點整理

多跳題的盲點答案要串起兩份以上的文件，而第二份該查什麼，要讀完第一份才知道。單次檢索的查詢只有原問題，補不了中間推出來的資訊。
交錯進行用問題檢索，讀段落，寫一句推理；再用這句推理檢索，讀新段落，寫下一句。每輪新段落加進集合，直到寫出答案或達到步數上限。
推理句就是查詢推理句把「換下的零件」換成具體的料號，查詢因此變得精準。論文在四個多跳資料集上報告檢索最多提升 21 個百分點、問答最多提升 15 個百分點。
代價與風險每輪一次檢索加一次 LLM 呼叫，延遲與成本隨輪數增加；一句推錯，後面會一路查錯。單跳問題不需要，先用路由判斷難度。

🧪 互動範例：一次檢索 vs. IRCoT

知識庫是 15 段虛構的工單、備品庫存表、技術通報與手冊。檢索是瀏覽器內真的在算（TF-IDF 餘弦相似度）；但推理句由預先寫好的腳本模擬（真實系統由 LLM 讀了檢索結果後產生）。請比較三件事：一次檢索取 k 段、一次檢索取 2k 段（段落預算與兩輪相同）、IRCoT 兩輪各取 k 段。「必要證據」是事先標好的兩段，看哪種做法把它們都找進來。

勾選「第 1 句推理出錯」可以看錯誤如何傳到下一輪。相似度只是詞袋近似，不代表真實嵌入模型。

k（每次取幾段）：
A. 一次檢索：取 k 段
B. 一次檢索：取 2k 段（同樣的段落預算）
C. IRCoT：兩輪，每輪取 k 段

💻 程式範例（Python）

下面是 IRCoT 迴圈的最小實作：retrieve 用 sentence-transformers 做向量檢索，每輪請 claude-sonnet-5 讀目前集合寫「下一句」推理，再拿這句去檢索。重點在迴圈結構：查詢、集合去重、停止條件與步數上限。

import numpy as np
import anthropic
from sentence_transformers import SentenceTransformer

model = SentenceTransformer("BAAI/bge-m3")
client = anthropic.Anthropic()

DOCS = [
    "WO-2026-0455：WTG-17 PT-203 旋角馬達過溫，更換旋角馬達，領用料號 PT-MTR-02。",
    "備品庫存表：料號 PT-MTR-02 旋角馬達，庫存 2 顆。",
    "備品庫存表：料號 YW-SNS-01 風向計，庫存 4 個。",
    "備品庫存表：料號 GB-BRG-07 齒輪箱高速軸軸承，庫存 1 組。",
]
D_VECS = model.encode(DOCS, normalize_embeddings=True)

def retrieve(query, k=2):
    q = model.encode([query], normalize_embeddings=True)[0]
    return [int(i) for i in np.argsort(-(D_VECS @ q))[:k]]

def next_sentence(question, pool, cot):
    ctx = "\n".join(DOCS[i] for i in pool)
    prompt = (f"段落：\n{ctx}\n\n問題：{question}\n已寫的推理：{' '.join(cot)}\n"
              "請只根據段落，寫出下一句推理（只寫一句）。若已能回答，以「答案是」開頭。")
    msg = client.messages.create(model="claude-sonnet-5", max_tokens=200,
                                 messages=[{"role": "user", "content": prompt}])
    return msg.content[0].text.strip()

def ircot(question, k=2, max_steps=4):
    pool = retrieve(question, k)                 # 第 1 輪：用原問題
    cot = []
    for _ in range(max_steps):                    # 步數上限，避免無限迴圈
        sentence = next_sentence(question, pool, cot)
        cot.append(sentence)
        if "答案是" in sentence:                 # 停止條件
            break
        for i in retrieve(sentence, k):           # 用這句推理當下一輪查詢
            if i not in pool:
                pool.append(i)
    return cot, pool

cot, pool = ircot("WO-2026-0455 換下的零件，現在還剩幾個？")
print(" ".join(cot))

實務上常加上：保留每輪的查詢與命中段落以便除錯、集合大小上限、無法收斂時回覆「查不到」。框架（如 LlamaIndex、LangGraph）也能把這個迴圈寫成多步流程，概念相同。

⚠️ IRCoT 常見的坑 / 何時不該用

  • 單跳問題：「PT-205 是什麼代碼」一次檢索就夠，多繞幾輪只是增加延遲與成本。可先用路由（第 015 堂）判斷難度。
  • 沒設步數上限：找不到證據時模型可能一直換說法重查。要設最大步數，並定義失敗時的回應。
  • 推理句出錯：第 1 句把料號寫錯，第 2 輪就查錯庫存表。要保留每輪的查詢與命中段落，必要時加入「推理句必須有段落支持」的檢查（第 028 堂）。
  • 查詢漂移：推理句越寫越長、越偏離原問題時，檢索會跑偏。可在查詢中保留原問題的關鍵條件，例如機型 OW-8。
  • 已知要查什麼：若兩個子問題彼此獨立，直接拆成多個查詢並行檢索更快（第 006、010 堂），不需要逐輪串行。
  • 段落集合膨脹：每輪都加段落，最後塞進提示的內容越來越多，要設上限並注意順序（第 031 堂）。
風場、機型、手冊、工單、料號與庫存數字皆為虛構，實際作業以原廠手冊與現場規範為準。互動範例的推理句是預寫腳本，不是真實的 LLM 輸出。

延伸閱讀：Trivedi、Balasubramanian、Khot 與 Sabharwal，Interleaving Retrieval with Chain-of-Thought Reasoning for Knowledge-Intensive Multi-Step Questions（ACL 2023）。

📝 小測驗

IRCoT 從第二輪開始，用什麼當檢索查詢？

每寫出一句推理，就用這句去檢索新段落，並把新段落加進集合，讓下一句推理能用到新的證據。

下列哪種問題最適合用 IRCoT？

B 需要先查 A 才知道要查 B，是典型的多跳問題；A 是單跳，一次檢索即可；C 不需要檢索。
