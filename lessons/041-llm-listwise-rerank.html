LLM 列表式重排：RankGPT 滑動窗口，讓模型一次比較多段

BM25 或向量檢索只看字面或語意相似，常把「關鍵字重複最多」的統計表、說明文排在最前面，真正能回答問題的排除步驟反而掉到後面。LLM 列表式重排（listwise reranking）把問題和多段候選一起交給大型語言模型，請它直接輸出一串排序編號，例如 [3] > [4] > [1]；候選太多放不進一次提示時，用由後往前的滑動窗口（sliding window）分批排序，把最相關的段落一路「帶」到最前面。

🎬 動畫：一次比較多段，滑動窗口把好段落接力往前送

🧩 重點整理

列表式：一次比較多段逐段打分（pointwise）的模型各看一段、分數彼此獨立；列表式把多段放進同一個提示，請 LLM 輸出排列（permutation），例如 [2] > [3] > [1]，模型能直接比較「哪段比較能回答」。
滑動窗口由後往前候選太多時，一次只排 w 段、每次往前移 s 段。由後往前掃，排在後面的好段落會被推到窗口頂端、落在重疊區，再被下一個窗口接力往前送。
一輪只保證前 w − s 名假設模型每次都排對，掃一輪後最相關的 w − s 段一定在最前面；第 w − s 名之後不一定正確。呼叫次數約為 (深度 − w) ÷ s + 1。
貴、慢、會受順序影響每次呼叫都要放 w 段全文，比 cross-encoder 貴得多；結果會受輸入順序與位置影響，輸出也可能漏號或重複。只救得回已進入候選清單的段落。

🧪 互動範例：BM25 排序 vs. LLM 滑動窗口重排

知識庫是虛構《OW-8 運維手冊》偏航系統（yaw）一章與相關文件，共 16 段；問題是「YW-042 偏航誤差過大，風向標讀值正常，要先查什麼？」。第一階段的 BM25 與滑動窗口流程都在瀏覽器裡真的計算；LLM 是示意：它每次只看得到窗口內的段落，依每段預先標註的相關度（0–3）排序，可選擇加入隨機雜訊模擬「偶爾排錯」。調整窗口大小 w、步長 s、重排深度與掃描方向，觀察呼叫次數、讀取段數與前 5 名品質（nDCG@5）的變化。

問題：
雜訊第 組（只在「偶爾排錯」時有作用）

💻 程式範例（Python）

下面是最小實作：先用 BM25（中文以二字詞切分）撈出候選，再照 RankGPT 的做法由後往前滑動窗口，每個窗口請 Claude 輸出 [i] > [j] 格式的排序。LLM 的輸出不一定乾淨，所以要用正規表示式抓編號、去掉重複與超出範圍的號碼，並把漏掉的編號依原順序補在最後。需要 pip install anthropic rank_bm25。

import re
import anthropic
from rank_bm25 import BM25Okapi

client = anthropic.Anthropic()
MODEL = "claude-sonnet-5"
DOCS = [  # 虛構《OW-8 運維手冊》偏航系統一章
    "YW-042 偏航誤差過大告警統計：彙整各機組去年告警次數，供年度報告使用。",
    "風向標讀值說明：風向標讀值是偏航控制的輸入，本節說明單位與更新頻率。",
    "YW-042 偏航誤差過大：機艙方向與風向平均偏差超過設定值即觸發。",
    "風向標安裝方位偏移時讀值看似正常，機艙卻固定偏一個角度，須以 GPS 羅經校正。",
    "機艙轉向遲緩時，先量測偏航煞車卡鉗殘餘壓力，確認放壓閥動作正常。",
    "偏航驅動馬達過載跳脫會使機艙轉不動；檢查馬達煞車與變頻器參數。",
    "扭纜感測器達上限時會自動解纜，解纜期間機艙方向暫時偏離屬正常。",
    "GB-117 齒輪箱高速軸軸承溫度過高：檢查油溫、油位與冷卻器。",
]

def bigrams(text):
    text = re.sub(r"\s+", "", text.lower())
    return [text[i:i + 2] for i in range(len(text) - 1)]

def first_stage(query, k=8):
    bm25 = BM25Okapi([bigrams(d) for d in DOCS])
    scores = bm25.get_scores(bigrams(query))
    return sorted(range(len(DOCS)), key=lambda i: -scores[i])[:k]

def rank_window(query, ids):
    """請 LLM 排序一個窗口內的段落，回傳重排後的文件編號。"""
    listing = "\n".join(f"[{j + 1}] {DOCS[i]}" for j, i in enumerate(ids))
    msg = client.messages.create(model=MODEL, max_tokens=100, messages=[{
        "role": "user",
        "content": f"以下 {len(ids)} 段以 [] 編號。\n{listing}\n\n問題：{query}\n"
                   "依與問題的相關程度由高到低排序，只輸出編號，格式如 [2] > [1] > [3]。"}])
    order = []
    for n in re.findall(r"\[(\d+)\]", msg.content[0].text):
        j = int(n) - 1
        if 0 <= j < len(ids) and j not in order:   # 去掉重複、超出範圍的編號
            order.append(j)
    order += [j for j in range(len(ids)) if j not in order]  # 漏掉的依原順序補上
    return [ids[j] for j in order]

def sliding_rerank(query, cands, w=4, s=2):
    cands = list(cands)
    start = max(0, len(cands) - w)            # 從最後一個窗口開始
    while True:
        cands[start:start + w] = rank_window(query, cands[start:start + w])
        if start == 0:
            return cands
        start = max(0, start - s)                  # 往前移 s 段，與上一窗重疊 w - s 段

q = "WTG-17 出現 YW-042 偏航誤差過大，風向標讀值正常，要先查什麼？"
cands = first_stage(q)
for rank, i in enumerate(sliding_rerank(q, cands)[:3], 1):
    print(rank, DOCS[i])

實務上要記錄每個窗口的輸入順序與 LLM 輸出，才看得出是第一階段沒撈到、還是重排排錯；並用評估集（第 021 堂）比較「BM25 + cross-encoder」與「BM25 + LLM 重排」的命中率、延遲與費用。若要降低成本，可參考論文的排列蒸餾：用 LLM 的排序結果訓練較小的重排模型。

⚠️ LLM 列表式重排常見的坑 / 何時不該用

  • 候選清單外救不回來：重排只改順序，不會找到新段落。互動範例把重排深度調到 6，「煞車殘壓」（BM25 第 7 名）就永遠進不了前 5。第一階段要撈得夠廣（混合檢索見第 004 堂）。
  • 步長太接近窗口：只掃一輪時，保證正確的只有前 w − s 名；s 接近 w 時重疊太少，好段落接力不上來。s = w 時窗口完全不重疊，好段落最多只能升到它所在窗口的頂端。
  • 方向弄反：由前往後掃會把最不相關的段落往後推，排在後面的好段落只能前進一個窗口。互動範例切到「由前往後」可以看到差異。
  • 受輸入順序與位置影響：Tang 等人（NAACL 2024）指出 LLM 的列表式排序會隨輸入順序改變，提出把清單打亂多排幾次再彙整（permutation self-consistency）。代價是呼叫次數再翻倍。
  • 輸出格式不可靠：模型可能漏號、重複、多說話或編出不存在的編號，一定要解析與補齊（程式範例的 rank_window）。候選段落中若夾帶指令，也可能干擾排序（第 024 堂）。
  • 何時不該用：延遲要求在一兩秒內、查詢量大、或 cross-encoder 已經夠準時，LLM 重排的費用與等待時間不划算；窗口要依序呼叫，難以平行。先用評估集確認提升幅度再上線。
風場、機型、手冊內容、告警代碼、技術通報與數據皆為虛構，實際作業以原廠手冊與現場規範為準。互動範例的 LLM 是依預先標註的相關度排序的示意，不是真實模型輸出。

📝 小測驗

RankGPT 的滑動窗口為什麼要「由後往前」掃？

每個窗口把最相關的段落排到窗口頂端；由後往前時，頂端正好是下一個窗口的重疊區，所以好段落能一路往前送。由前往後則只能前進一個窗口。

候選 40 段、窗口 w = 10、步長 s = 5，只掃一輪。假設 LLM 每次都排對，哪個說法正確？

呼叫次數 = (40 − 10) ÷ 5 + 1 = 7。一輪只保證前 w − s = 5 名正確，其餘名次不一定。
