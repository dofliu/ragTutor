第 040 堂高階約 15 分鐘

Speculative RAG：小模型平行打草稿，大模型只負責挑

檢索回來 10 段，一般 RAG 把它們全部塞給大模型：輸入很長、又慢又貴，無關段落和「中段遺失」也跟著進來。Speculative RAG 先把檢索結果分群，每群抽一段組成多個小子集；小模型（草稿者 drafter）各讀一個子集、平行寫出「答案草稿＋理由」，大模型（驗證者 verifier）只替草稿打分，挑出最好的一份。

🎬 動畫：分群抽樣、平行打草稿、一次驗證

🧩 重點整理

草稿與驗證分工小而專的模型讀少量段落、平行寫多份草稿；大模型不再讀全部原文，只替草稿打分並挑一份。概念類似推測解碼（speculative decoding）。
分群再抽樣先依內容把檢索結果分成 k 群，每個子集從每群各抽 1 段。每份草稿看到不同觀點，輸入也只有 k 段，減少長輸入與位置偏差。
驗證分數三項相乘論文的分數是草稿者的自信、驗證者眼中草稿與理由的一致性、以及「理由是否支持答案」的反思分數相乘，取最高分的草稿。
代價在別處需要專門微調的草稿模型、多個平行端點；驗證者看不到原文，只能相信理由。論文報告的提升是公開資料集上的數字，請在自己的資料上驗證。

🧪 互動範例：一般 RAG vs Speculative RAG

知識庫是 10 段虛構的檢索結果，問題是「PT-211 三支葉片角度偏差過大，先檢查什麼？」。分群（K-Means，TF-IDF 向量）、抽樣與檢索分數都是瀏覽器裡真的在算；草稿者與驗證者是示意：草稿 = 子集中與問題最相關的一句，驗證分數 = 草稿與問題的相似度 × 理由（子集）與問題的相似度。調整群數 k、草稿數 m，或改成「不分群、隨機抽」，觀察草稿涵蓋的觀點與輸入長度的變化。

問題：
抽樣第 次

💻 程式範例（Python）

下面是最小實作：用 TF-IDF（中文以二字詞）＋ K-Means 分群，每群抽 1 段組成 m 個子集；草稿者用較小的模型平行寫「答案＋理由」，驗證者一次讀所有草稿並打分。論文的驗證者是讀取詞機率算分，Claude API 不提供詞機率，這裡改成請驗證者直接給分，屬於簡化做法。

import json, random
import anthropic
from concurrent.futures import ThreadPoolExecutor
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.cluster import KMeans

client = anthropic.Anthropic()
DRAFTER = "claude-haiku-5-5"    # 小而快的草稿者；論文用微調過的 7B 模型
VERIFIER = "claude-sonnet-5"    # 大模型只負責驗證
DOCS = [  # 檢索回來的 top-n 段（虛構）
    "PT-211 三支葉片角度偏差過大時，先比對三支葉片的角度編碼器讀值，找出偏移的葉片。",
    "角度編碼器零點偏移時，須以校正治具重新歸零，並記錄於工單。",
    "若確認為單一葉片實際偏移，須檢查該軸旋角減速機的背隙與齒面。",
    "旋角軸承潤滑不足會增加轉動阻力，使該葉片跟不上設定角度。",
    "PT-230 旋角備援電源測試失敗時，先檢查電池組電壓。",
    "進入輪轂前須先順槳並鎖定葉輪，並執行上鎖掛牌（LOTO）。",
]

def ask(model, prompt, max_tokens=400):
    msg = client.messages.create(model=model, max_tokens=max_tokens,
                                 messages=[{"role": "user", "content": prompt}])
    return msg.content[0].text

def make_subsets(docs, k=3, m=4, seed=0):
    X = TfidfVectorizer(analyzer="char", ngram_range=(2, 2)).fit_transform(docs)
    labels = KMeans(n_clusters=k, n_init=10, random_state=seed).fit_predict(X)
    groups = [[i for i, c in enumerate(labels) if c == g] for g in range(k)]
    rng, subsets = random.Random(seed), set()
    for _ in range(100):                          # 每群抽 1 段，湊滿 m 個不同子集
        subsets.add(tuple(sorted(rng.choice(g) for g in groups)))
        if len(subsets) == m: break
    return list(subsets)

def draft(question, subset):
    ctx = "\n".join(f"[{i}] {DOCS[i]}" for i in subset)
    return ask(DRAFTER, "只依據資料，用一句話回答，再用一句話寫理由（註明段落編號）。\n"
               f"資料：\n{ctx}\n問題：{question}")

def verify(question, drafts):
    listing = "\n\n".join(f"草稿 {j}：\n{d}" for j, d in enumerate(drafts))
    out = ask(VERIFIER, "替每份草稿打 0–10 分：答案是否回答問題、理由是否支持答案。"
              "只輸出 JSON 整數陣列。\n" + f"問題：{question}\n{listing}")
    scores = json.loads(out)
    return drafts[max(range(len(drafts)), key=lambda j: scores[j])]

def speculative_rag(question):
    subsets = make_subsets(DOCS)
    with ThreadPoolExecutor() as pool:           # 草稿彼此獨立，平行產生
        drafts = list(pool.map(lambda s: draft(question, s), subsets))
    return verify(question, drafts)                # 驗證者只讀草稿，不讀原文

print(speculative_rag("WTG-23 出現 PT-211 三支葉片角度偏差過大，先檢查什麼？"))

實務上要把每個子集、每份草稿與分數都記錄下來，才看得出是分群抽樣沒抽到關鍵段落，還是驗證者挑錯；並用評估集（第 021 堂）同時比較準確率、延遲與總花費，和直接把 top-n 交給大模型的一般 RAG 對照。

⚖️ 與前面課程的比較

一般 RAG（第 001 堂）上下文壓縮（第 012 堂）Self-RAG（第 013 堂）Speculative RAG
要解決讓模型有依據上下文太長、雜訊多何時檢索、內容可不可信大模型讀太多段，又慢又雜
做法top-n 全交給模型先刪掉無關句子模型輸出反思標記自我評估分群抽樣 → 小模型平行草稿 → 大模型驗證
大模型讀什麼全部段落壓縮後的段落段落（同一個模型邊寫邊評）只讀草稿與理由
額外成本無一次壓縮需訓練會輸出反思標記的模型需微調草稿模型、多個平行端點
主要風險長輸入、中段遺失刪掉關鍵句反思判斷錯誤抽樣漏掉關鍵段、驗證者看不到原文

⚠️ Speculative RAG 常見的坑 / 何時不該用

  • 關鍵段落沒被抽到：每群只抽 1 段，若關鍵段落所在的群很大，m 太小時可能沒有任何子集包含它（互動範例把 m 調成 1 可以看到）。要保證 m 夠大，或在抽樣時讓排名較前的段落有較高機率。
  • 分群沒有意義：群數 k 不合適，或嵌入沒有反映問題相關的差異，子集就只是隨機組合。論文用以問題為條件的嵌入模型分群。
  • 草稿模型不夠可靠：論文的草稿者是專門微調過的模型；直接拿未調整的小模型，草稿品質可能撐不起驗證。換領域要準備訓練資料。
  • 驗證者看不到原文：它只看草稿與理由，理由寫錯時很難發現。安全相關結論要附出處（第 025 堂），並由人覆核。
  • 總花費未必降低：延遲靠平行，m 份草稿就是 m 次小模型呼叫；如果只有一個端點、或問題很簡單（單一段落就能回答），一般 RAG 反而更省。
  • 需要多段整合的答案：每份草稿只讀 k 段，若答案必須同時引用很多段落，單一草稿可能不完整，要評估是否改用多跳（第 034 堂）或問題分解（第 039 堂）。
風場、機型、手冊內容、告警代碼、工單與數據皆為虛構，實際作業以原廠手冊與現場規範為準。互動範例的草稿者與驗證者是用相似度計算的示意，不是真實模型輸出。

延伸閱讀：Wang 等人，Speculative RAG: Enhancing Retrieval Augmented Generation through Drafting（ICLR 2025，arXiv 2407.08223）；推測解碼見 Leviathan 等人，Fast Inference from Transformers via Speculative Decoding（arXiv 2211.17192）。

📝 小測驗

在 Speculative RAG 裡，大模型（驗證者）主要做什麼？

草稿由小模型平行產生；大模型只讀草稿與理由並打分，不必讀全部原文，所以能降低延遲。

為什麼要先分群，再「每群抽 1 段」組成子集？

每群代表一類觀點；每群抽 1 段讓子集兼顧多元與簡短。這需要嵌入向量來分群。
