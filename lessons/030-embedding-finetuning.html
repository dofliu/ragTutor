領域嵌入微調：用合成查詢與困難負例，教嵌入模型聽懂你的領域

通用嵌入模型沒看過風場的語料，技師說「葉片轉不動」，它不知道這常指向「煞車卡住」。與其一直改提示詞，不如微調嵌入模型本身：用 LLM 替沒標註的工單合成（問題, 段落）配對，以對比學習拉近正例、推遠負例，再挖困難負例逼模型分辨相似段落，最後用沒練過的真實問法驗收。

🎬 動畫：從通用模型到領域模型

🧩 重點整理

配對資料靠合成讓 LLM 讀無標註的段落，反推技師口吻的問題，得到（問題, 段落）配對。提示詞要規定口吻，並用既有檢索過濾掉太籠統的問題。
對比學習拉近與推遠正確配對的向量被拉近；同一個 batch 內其他段落自動當負例（in-batch negatives）。batch 越大，負例越多。
困難負例教細節，也有風險「很像但不是答案」的段落最有教學價值，但也最容易挖到偽負例（其實也能回答）。可用 cross-encoder 過濾或改用軟標籤（GPL）。
用留出集驗收，換模型要重建索引合成問題上變好不代表真的更好，要用沒練過的真實問法量 Recall@k，並檢查通用問題有沒有退步；模型一換，整份索引要重新嵌入。

🧪 互動範例：加入合成配對與困難負例

下面有 8 段維修工單（虛構）。左邊是「未微調」的向量檢索（TF-IDF 模擬通用嵌入）；右邊是用你選的合成配對數「微調」後的版本。測試用的 4 個問法沒有出現在訓練配對裡，只是和訓練問法有部分共用的詞。可以切換是否使用困難負例，看看相似段落（PT-203 與 PT-205）會不會被混淆。

這是簡化模擬：真實微調是調整神經網路的權重；這裡只用「訓練配對教出的詞對應」來擴充查詢向量，用來看清楚資料怎麼影響結果，不代表任何真實模型的行為與數字。

💻 程式範例（Python）

用 anthropic 替工單合成問題，再用 sentence-transformers 以 MultipleNegativesRankingLoss 微調。損失函數的輸入是（問題, 正例）或（問題, 正例, 困難負例）三元組，同一個 batch 內的其他正例會自動成為 in-batch negatives。範例用的基底模型名稱請換成你選用、支援中文的嵌入模型；資料量與超參數需自行調整與評估。

import json, anthropic
from sentence_transformers import SentenceTransformer, losses, InputExample
from torch.utils.data import DataLoader

client = anthropic.Anthropic()

PASSAGES = [
    "WO-2026-0412 WTG-07 PT-205：旋角馬達煞車線圈供電不穩，葉片角度卡住，更換煞車組 PT-BRK-02 後恢復。",
    "WO-2026-0415 WTG-12 PT-203：旋角馬達過溫跳脫，冷卻風扇濾網積塵，清潔濾網並降溫後復歸。",
    "WO-2026-0420 WTG-21 PT-230：備援電源測試失敗，電池電壓偏低，更換電池模組。",
]

def synth_queries(passage, n=3):
    """讓 LLM 以現場技師的口吻，替一段工單反推 n 個問題"""
    msg = client.messages.create(
        model="claude-sonnet-5", max_tokens=400,
        messages=[{"role": "user", "content":
            f"以下是風機維修工單。請用現場技師的口語，寫出 {n} 個可以用這段工單回答的簡短問題，"
            f"不要直接照抄工單用字。只回傳 JSON 字串陣列。\n\n{passage}"}],
    )
    return json.loads(msg.content[0].text)

# 1) 合成（問題, 段落）配對
pairs = [(q, p) for p in PASSAGES for q in synth_queries(p)]

# 2) 用現有模型挖困難負例：排名前面、但不是該問題的正解段落
base = SentenceTransformer("你的基底嵌入模型")
p_emb = base.encode(PASSAGES, normalize_embeddings=True)
examples = []
for q, pos in pairs:
    scores = p_emb @ base.encode(q, normalize_embeddings=True)
    ranked = [PASSAGES[i] for i in scores.argsort()[::-1] if PASSAGES[i] != pos]
    # 實務上要再用 cross-encoder 過濾偽負例，或跳過最前面幾名
    examples.append(InputExample(texts=[q, pos, ranked[0]]))

# 3) 對比學習微調（同一個 batch 的其他正例自動成為 in-batch negatives）
loader = DataLoader(examples, shuffle=True, batch_size=32)
loss = losses.MultipleNegativesRankingLoss(base)
base.fit(train_objectives=[(loader, loss)], epochs=1, warmup_steps=10)
base.save("ow8-embedder-v1")   # 換模型後，整份索引都要用新模型重新嵌入

上線前要用留出的真實問法（第 021 堂）比較微調前後的 Recall@k，並同時檢查通用問題有沒有退步。若 fit 介面在你安裝的 sentence-transformers 版本不同，請依官方文件調整；訓練也可改用較新的 Trainer 介面。

⚠️ 嵌入微調常見的坑 / 何時不該用

  • 偽負例：把其實能回答的段落當負例，會把模型教壞。挖困難負例時要過濾（cross-encoder 打分、跳過頂端排名），或改用軟標籤。
  • 在合成問題上驗收：訓練與驗收用同一批合成問題，數字一定漂亮。要留一批真實問法（或人工審過的問題）當測試集。
  • 合成問題品質差：LLM 若照抄原文用字，模型只學到「字面比對」；要在提示詞中要求口語、換說法，並抽樣檢查。
  • 遺忘通用能力：只用單一領域資料訓練太久，可能讓一般問題變差。控制訓練量，並同時評估通用問題。
  • 模型一換，索引全重來：向量空間改變，舊向量不能與新模型的查詢向量混用，必須整份重新嵌入。要規劃版本與切換流程。
  • 先試便宜的方法：查詢改寫、混合檢索、重排序、情境化檢索常常已足夠。資料量小、用語常變，或沒有評估集時，不建議一開始就微調。
  • 資料外洩與授權：把內部工單送到外部 LLM 合成問題前，先確認資料分級與授權（第 024 堂）。
風場、機型、手冊與工單內容及數據皆為虛構，實際作業以原廠手冊與現場規範為準。互動範例是簡化模擬，不代表真實微調的行為與數字。

延伸閱讀：Wang 等人，GPL: Generative Pseudo Labeling for Unsupervised Domain Adaptation of Dense Retrieval（NAACL 2022）；Sentence Transformers 官方文件中的 MultipleNegativesRankingLoss 與訓練說明。

📝 小測驗

為什麼挖「困難負例」時，要擔心偽負例？

知識庫常有多段內容都能回答同一問題；「排名高但不是標註正解」不等於「錯」。可用 cross-encoder 過濾或跳過最前面幾名。

微調嵌入模型並上線後，下列哪件事一定要做？

新舊模型的向量空間不同，不能混用；查詢與文件必須由同一個模型嵌入，所以要整份重新嵌入。
