基礎 RAG：讓大型語言模型「先查資料再回答」

Retrieval-Augmented Generation（檢索增強生成）是把「搜尋」接在「生成」前面的架構。模型不再只靠訓練時記住的知識，而是每次回答前，先從你的資料中找出相關段落，再根據這些段落作答。

🎬 動畫：一個問題的旅程

🧩 重點整理

2 個階段索引（離線）把文件切塊、嵌入、存進向量資料庫；查詢（線上）檢索相關片段並交給 LLM。
不必重新訓練知識更新只要重新索引文件，模型權重完全不動。
可附出處答案能回溯到哪一個片段，方便使用者查證。
品質瓶頸在檢索找錯片段，再強的模型也會答錯——後續課程的技術大多在改善這一步。

🧪 互動範例：親手跑一次檢索

下面是一份虛構的「星河科技員工手冊」，已經切成 8 個片段。輸入問題後，瀏覽器會把問題與每個片段轉成向量（這裡用中文二元組的 TF-IDF 模擬嵌入），計算餘弦相似度，取出最相關的 k 個片段，最後組出要送給 LLM 的 Prompt。

送給 LLM 的 Prompt

💻 程式範例（Python）

一個最小可運作的 RAG：sentence-transformers 產生嵌入、NumPy 做相似度，再把片段放進 Prompt 交給 Claude 生成。

import numpy as np
from sentence_transformers import SentenceTransformer
import anthropic

# ① 索引階段：切塊 → 嵌入 → 存起來
chunks = ["國內出差住宿每晚上限 2,800 元，需檢附收據。",
          "員工每年享有 14 天特休，未休完可遞延一年。",
          "遠端工作每週最多 2 天，需事先於系統登記。"]
embedder = SentenceTransformer("BAAI/bge-m3")
vectors = embedder.encode(chunks, normalize_embeddings=True)

# ② 查詢階段：問題嵌入 → 相似度 → Top-k
def retrieve(question, k=2):
    q = embedder.encode([question], normalize_embeddings=True)[0]
    scores = vectors @ q                      # 已正規化 → 內積即餘弦相似度
    top = np.argsort(-scores)[:k]
    return [chunks[i] for i in top]

def answer(question):
    context = "\n".join(f"[{i+1}] {c}" for i, c in enumerate(retrieve(question)))
    prompt = ("只根據下列參考資料回答，並標註出處編號；資料中沒有就說不知道。\n\n"
              f"參考資料：\n{context}\n\n問題：{question}")
    client = anthropic.Anthropic()
    msg = client.messages.create(model="claude-sonnet-5", max_tokens=512,
                                 messages=[{"role": "user", "content": prompt}])
    return msg.content[0].text

print(answer("出差住宿每晚可以報多少？"))

⚠️ 基礎 RAG 常見的坑

  • 切塊切壞了：一句話被切成兩半，答案所需的上下文散落在不同片段。→ 下一堂「切塊策略」。
  • 語意相近但不相關：向量檢索只看「像不像」，專有名詞、料號、法條編號容易漏掉。→「混合檢索」。
  • Top-k 的兩難：k 太小漏掉資訊，k 太大塞進雜訊、稀釋模型注意力。→「重排序」。
  • 問題本身太模糊：「那個規定呢？」這種問題很難檢索。→「查詢改寫」。
範例中的員工手冊內容與數字皆為虛構，只用於教學示範。

📝 小測驗

公司的報帳規定每季都會修改，想讓 AI 助理永遠回答最新版本，最適合的做法是？

RAG 把「知識」放在外部資料庫，更新文件後重新切塊與嵌入即可，不必動模型；還能附上出處讓員工查證。
