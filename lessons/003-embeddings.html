嵌入與向量檢索：從「像不像」到毫秒級找到最相似的幾筆

當資料庫裡有幾百萬筆嵌入向量，不可能每次查詢都跟每一筆比對一次。這堂課會看懂餘弦相似度怎麼衡量兩個向量「像不像」，以及當資料量大到暴力法撐不住時，近似最近鄰（Approximate Nearest Neighbor, ANN）索引——特別是最常見的圖狀索引 HNSW——如何用遠少於全部資料筆數的比較次數，換來幾乎一樣準確的結果。

🎬 動畫：從暴力法比對到 HNSW 分層搜尋

🧩 重點整理

嵌入把內容變成向量句子、片語甚至圖片都能被嵌入模型轉成一串固定長度的數字，語意相近的內容在向量空間裡的距離也相近。
餘弦相似度看方向不看長度比較兩個向量的夾角，是最常見的「像不像」量尺，跟向量的長度（大小）無關。
暴力法保證正確但線性成長要跟資料庫裡每一筆都比對一次，資料筆數變兩倍，比對次數也大約變兩倍。
ANN 用少量誤差換速度HNSW 等圖狀索引只跟一小部分鄰居比較，用遠低於資料筆數的比對次數，換來接近暴力法的準確度。

🧪 互動範例：暴力法 vs. 圖形 ANN，實際比一次

下面是一份虛構的「晴果 3C 配件」線上賣場常見問答，共 30 筆，分成退換貨、保固、運送、商品規格、付款五類；也可以切換成《OW-8 運維手冊》的 30 個段落，分成旋角、偏航、齒輪箱、發電機與變流器、工安五類。切換「暴力法」與「圖形 ANN（模擬 HNSW 概念）」，並調整 ef（搜尋候選清單大小）與 M（每個節點的鄰居數），看看比對次數怎麼變化，以及找到的結果跟暴力法是否一致。

💻 程式範例（Python）

餘弦相似度、暴力法，以及一個簡化版的圖狀索引（NSW 的核心概念：只幫每個節點保留最相似的 M 個鄰居，查詢時沿著鄰居移動，不跟全部節點比對）。

import numpy as np

# ① 餘弦相似度：只看方向，不看向量長度
def cosine(a, b):
    return float(a @ b) / (np.linalg.norm(a) * np.linalg.norm(b) + 1e-9)

# ② 暴力法：保證正確，但要跟每一筆都比對一次
def brute_force_search(query_vec, vectors, k=3):
    scores = [cosine(query_vec, v) for v in vectors]
    order = np.argsort(scores)[::-1][:k]
    return [(i, scores[i]) for i in order]

# ③ 建立簡化版圖狀索引：每個節點只保留最相似的 M 個鄰居
def build_graph(vectors, M=4):
    n = len(vectors)
    graph = {i: set() for i in range(n)}
    for i in range(n):
        order = sorted((j for j in range(n) if j != i),
                       key=lambda j: -cosine(vectors[i], vectors[j]))
        for j in order[:M]:
            graph[i].add(j); graph[j].add(i)          # 邊視為雙向
    return graph

# ④ 貪婪圖搜尋：從入口點出發，只跟走訪過的鄰居比較
def greedy_search(query_vec, vectors, graph, entry=0, ef=4, k=3):
    scored = lambda i: cosine(query_vec, vectors[i])
    visited = {entry}
    candidates = [(scored(entry), entry)]
    found = [(scored(entry), entry)]
    while candidates:
        candidates.sort(reverse=True)
        score, cur = candidates.pop(0)
        found.sort(reverse=True)
        if len(found) >= ef and score < found[ef - 1][0]:
            break                                       # 已經找不到更好的候選，提前停止
        for nb in graph[cur]:
            if nb in visited:
                continue
            visited.add(nb)
            s = scored(nb)
            candidates.append((s, nb)); found.append((s, nb))
    found.sort(reverse=True)
    return found[:k], len(visited)                          # len(visited) 就是實際比對次數

⚠️ 向量檢索常見的坑 / 何時不該用

  • 資料量小就別急著上 ANN：多一層索引結構與調參成本，可能超過它省下來的運算時間；先量測暴力法的實際查詢表現，資料量真的大到撐不住時再換成 ANN 索引。
  • ef / M 沒調好：太小會漏掉真正相關的結果（召回率低），太大則失去 ANN 原本要節省的比對次數與記憶體，兩者都要依實際資料實測調整，沒有放諸四海皆準的預設值。
  • 圖狀索引不容易刪除節點：像 HNSW 這類索引刪除節點會破壞圖的連通性，常見做法是先標記為已刪除、之後再整批重建索引，而不是即時物理刪除。
  • 距離度量要跟嵌入模型一致：有些嵌入模型的輸出只有在用餘弦相似度或內積比較時才有意義，如果索引用歐幾里得距離建立，排序結果可能不符預期。
  • 相似不等於正確：ANN 只保證找到向量空間裡「距離夠近」的候選，不保證語意完全符合問題，仍要靠後續的重排序或生成模型把關。

📝 小測驗

假設向量資料庫中有 1000 萬筆嵌入向量，若使用暴力法（brute-force）逐一比對餘弦相似度來回答一次查詢，運算量大致會如何隨資料筆數變化？

暴力法要跟每一筆向量都算一次相似度，才能保證找到真正最相似的結果，所以運算量會隨資料筆數線性成長；這正是資料量大的系統需要 ANN 索引的原因。

下列關於 HNSW 的敘述，何者正確？

HNSW 是分層圖狀索引：上層節點少、連結長，適合快速跳到大致正確的區域；下層節點多、連結短，適合做細部比較。它屬於近似最近鄰搜尋，為了速度犧牲了「保證找到最相似」的性質，但通常能取得很高的召回率。
