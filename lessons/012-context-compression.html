第 012 堂進階約 12 分鐘

上下文壓縮：只留下與問題有關的句子

技師問「PT-203 旋角馬達過溫怎麼處理」，檢索回來的是手冊整節旋角系統故障排除，裡面還有 PT-205 煞車、PT-211 角度偏差、備援電源與完工填單。整段塞給 LLM，token 浪費、延遲變高，模型也更容易被無關內容分心。上下文壓縮（Contextual Compression）在檢索與 LLM 之間加一道壓縮器，依問題只留下有關的句子；它是第 008 堂「小塊檢索、大塊回傳」的反向動作：回傳大塊之後，再把用不到的部分裁掉。

🎬 動畫：檢索之後、送進 LLM 之前，先裁一刀

🧩 重點整理

壓縮發生在檢索之後檢索器決定「找哪些文件」，壓縮器決定「文件裡留哪些內容」。壓縮器同時看問題與文件，所以每次提問的壓縮結果都不同。
三種常見做法相似度門檻（便宜、不用 LLM）、LLM 抽取（較準、每份文件多一次呼叫）、專用壓縮器或詞元修剪（RECOMP、LLMLingua，壓得更狠）。
抽取比改寫安全只挑出原句、不改寫，數字、告警代碼與步驟順序才不會被改錯，也能追溯來源。讓 LLM 回傳句子編號，是實務上常見的穩健做法。
必保留的內容要用規則安全注意事項與問題字面可能不像，卻絕不能丟。用中繼資料標註、壓縮後強制補回，不要賭相似度或 LLM 的臨場判斷。

🧪 互動範例：同一節手冊，四種壓縮方式

下面是虛構《OW-8 運維手冊》3.4 節「旋角系統故障排除」的 12 個句子（原順序）。輸入問題（或點範例），選擇壓縮方式：相似度門檻與 Top-K 是真的在瀏覽器裡逐句算分（簡化的 TF-IDF 餘弦相似度，不是真正的嵌入）；LLM 抽取無法在網頁內執行，這裡以人工標註的「理想結果」模擬，真實 LLM 會有誤差。拖動滑桿觀察「保留多少、漏掉什麼、混進什麼」，並試試勾選「強制保留安全注意事項」。

💻 程式範例（Python）

把手冊一節切成句子，示範兩種壓縮：①用嵌入相似度加門檻；②請 claude-sonnet-5 只回傳要保留的句子編號，程式再取回原句。兩者都加上「安全注意事項一律保留」的規則。範例文件為虛構；相似度門檻要用自己的資料與嵌入模型校準，這裡的 0.45 只是示意。

import json, re
import anthropic
from sentence_transformers import SentenceTransformer

client = anthropic.Anthropic()
embedder = SentenceTransformer("BAAI/bge-m3")

# 檢索回來的整節手冊（虛構的 OW-8 運維手冊 3.4 節）
SECTION = """PT-203 旋角馬達過溫：繞組溫度超過門檻時，控制器會限制電流並使旋角馬達跳脫。
讀取近 24 小時的旋角馬達溫度曲線，確認過溫是持續升溫還是瞬間尖峰。
PT-205 旋角馬達煞車異常：煞車釋放時間超過設定值時，請檢查煞車線圈電壓與摩擦盤間隙。
檢查旋角馬達的散熱風道是否被灰塵或油污堵塞，並確認冷卻風扇運轉正常。
作業前必須完成上鎖掛牌（LOTO），確認風機已停機且旋角系統斷電。
量測馬達溫度感測器（PT100）的阻值並檢查接線，感測器斷線也會誤報過溫。
進入輪轂前須確認葉輪鎖已插入，並由第二人在輪轂外待命。
完成排除後，請在工單填寫處理摘要，並記錄告警代碼與更換的零件。"""

# 規則：含這些關鍵詞的句子視為安全注意事項，一律保留（實務上建議改用中繼資料標註）
MUST_KEEP = ("上鎖掛牌", "LOTO", "葉輪鎖")

def split_sentences(text):
    return [s.strip() for s in re.split(r"(?<=[。！？])\s*", text) if s.strip()]

def must_keep(sentence):
    return any(w in sentence for w in MUST_KEEP)

# ① 相似度門檻：逐句和問題算餘弦相似度
def compress_by_similarity(question, sents, threshold=0.45):
    vecs = embedder.encode(sents + [question], normalize_embeddings=True)
    scores = vecs[:-1] @ vecs[-1]
    return [s for s, sc in zip(sents, scores) if sc >= threshold or must_keep(s)]

# ② LLM 抽取：只回傳句子編號，不讓模型改寫原文
def compress_by_llm(question, sents):
    numbered = "\n".join(f"[{i}] {s}" for i, s in enumerate(sents))
    msg = client.messages.create(
        model="claude-sonnet-5", max_tokens=100,
        messages=[{"role": "user", "content":
            "以下是風機手冊的句子。請只回傳與問題直接相關的句子編號，"
            "格式為 JSON 整數陣列，例如 [0, 2]；都不相關就回傳 []。\n"
            f"問題：{question}\n{numbered}"}])
    ids = json.loads(msg.content[0].text)
    # 模型輸出不可盡信：只接受合法編號，再補回必保留句，並維持原順序
    keep = {i for i in ids if isinstance(i, int) and 0 <= i < len(sents)}
    keep |= {i for, s in enumerate(sents) if must_keep(s)}
    return [sents[i] for i in sorted(keep)]

sents = split_sentences(SECTION)
question = "PT-203 旋角馬達過溫怎麼處理"
for name, fn in [("相似度", compress_by_similarity), ("LLM", compress_by_llm)]:
    kept = fn(question, sents)
    print(f"【{name}】{len(sents)} 句 → {len(kept)} 句")
    for s in kept:
        print(" -", s)

若用 LangChain，等價的做法是 ContextualCompressionRetriever 搭配 EmbeddingsFilter（相似度過濾）或 LLMChainExtractor（LLM 抽取）；這些類別的介面隨版本調整，請以官方文件為準。

⚖️ 三種做法比較

重排序（第 005 堂）父子文件檢索（第 008 堂）上下文壓縮（本堂）
作用對象決定「哪幾份文件」排前面決定「回傳多大一塊」決定「一份文件裡留哪些內容」
對上下文長度不改變每份文件長度，只取較少份變長：小塊命中、大塊回傳變短：回傳之後再裁掉無關句子
額外成本每個候選一次 cross-encoder 運算多存一份父文件、無額外模型呼叫門檻法幾乎免費；LLM 抽取每份文件一次呼叫
主要風險候選沒召回就救不回來大塊帶入較多雜訊壓錯就看不到，必保留的內容可能被丟

三者可以串接：先召回、重排序取前幾名，用父子文件撈回完整章節，最後壓縮成與問題有關的句子。壓縮和「重排序後只取 Top-3」並不衝突，一個管份數，一個管每份的長度。

⚠️ 上下文壓縮常見的坑 / 何時不該用

  • 安全注意事項被當成雜訊丟掉：互動範例用「相似度門檻」，LOTO 與葉輪鎖兩句會消失，看起來答案反而更精簡。必須保留的內容要用規則（中繼資料標註、關鍵詞白名單）強制補回。
  • 讓 LLM 改寫會改錯內容：摘要式壓縮可能把「每 6 個月」寫成「每半年左右」，也可能漏掉告警代碼。手冊這類精確內容，優先用抽取式，並讓 LLM 回傳編號、由程式取回原句。
  • 壓縮本身有成本：LLM 抽取每份文件多一次呼叫，延遲與費用可能抵銷省下的 token。先量測「壓縮前後的總成本與答案品質」再決定。
  • 句子脫離上下文：切成單句後，「依上節步驟」「同上」這類指代會失去意義（第 009 堂的問題）。可以保留相鄰句，或把句子所屬的章節標題一起帶上。
  • 門檻不能一勞永逸：不同問題、不同嵌入模型的相似度分布不同。互動範例中門檻稍高就開始漏掉正解；要用評估集校準，並追蹤「必要句召回率」。
  • 要保留來源：壓縮後仍要記得每一句來自哪一節、哪個版本，答案才能附上引用，技師也才能回頭查原文。
  • 文件本來就短，或模型上下文夠大時不必做：段落只有幾句、或總長度遠低於上下文限制且成本可接受時，多一道壓縮只增加複雜度與出錯機會。
風場、機型、手冊內容與數據皆為虛構，實際作業以原廠手冊與現場規範為準。互動範例的檢索為簡化的 TF-IDF 模擬，「LLM 抽取」以人工標註模擬；範例中的告警代碼、步驟、天數與門檻僅供教學示範。

延伸閱讀：RECOMP（Xu、Shi、Choi，2023）提出抽取式與摘要式壓縮器；LLMLingua（Jiang 等人，EMNLP 2023）以小型語言模型修剪提示詞；Lost in the Middle（Liu 等人，2023）討論長上下文中資訊位置對表現的影響。

📝 小測驗

上下文壓縮與重排序（第 005 堂）最主要的差別是什麼？

重排序調整的是文件的順序與取捨，不改變每份文件本身；壓縮則縮短每份文件，讓送進 LLM 的上下文更短、更聚焦。兩者作用對象不同，可以一起使用。

用相似度門檻壓縮手冊時，為什麼「上鎖掛牌（LOTO）」那句容易被丟掉？該怎麼處理？

相似度只反映「和問題像不像」，安全注意事項卻是「無論如何都要讀到」的內容。把門檻調到 0 等於不壓縮；正確做法是以規則保底，不把必保留的內容交給相似度或 LLM 臨場判斷。
