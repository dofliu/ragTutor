第 016 堂高階約 16 分鐘

RAPTOR：遞迴摘要樹檢索

技師問「旋角系統有哪些定期保養項目」，答案散在手冊好幾節：每季、每半年、每年的項目各寫在不同小段。一般 RAG 只取前幾個小塊，漏項是必然的。RAPTOR 先把小塊依語意分群、請 LLM 寫摘要，摘要再分群再摘要，由下而上建成一棵摘要樹。查詢時從整棵樹找，全局問題命中高層摘要，細節問題命中底層原文。

🎬 動畫：把手冊建成一棵摘要樹

🧩 重點整理

遞迴建樹RAPTOR（Sarthi 等人，ICLR 2024）把文件切成小塊（葉節點），重複「嵌入、分群、摘要」，由下而上得到不同抽象層次的節點。
摘要也是可檢索的節點摘要會被嵌入並放進索引，所以「有哪些保養項目」這類需要整合多段的全局問題，能直接命中一則概括的摘要。
兩種查詢法樹遍歷由根逐層往下選；collapsed tree 把所有層攤平一起比。原論文的實驗中，collapsed tree 表現較好，因為它能依問題自行挑層級。
用建樹成本換全局視野建樹要大量 LLM 摘要呼叫，文件更新時摘要要重做；若問題都是查單一告警代碼，這筆成本就不划算。

🧪 互動範例：只查原文切塊 vs 查整棵摘要樹

下面是虛構的《OW-8 運維手冊》旋角系統保養章節：8 個葉節點、3 則第一層摘要、1 則根摘要。摘要是我事先寫好的（沒有真的呼叫 LLM），檢索則是在瀏覽器裡用簡化的 TF-IDF 餘弦相似度真的算。選一個問題與檢索方式，調整 k，看取回的節點涵蓋了多少「必要的原文切塊」（摘要節點算涵蓋它底下所有葉節點）。你也可以輸入自己的問題，只是「必要」的標註僅限預設題。

💻 程式範例（Python）

最小實作：用 TF-IDF 字元 n-gram 當嵌入、KMeans 分群（原論文用 SBERT 嵌入、UMAP + GMM，這裡為了好執行而簡化），摘要與回答用 claude-sonnet-5。先 pip install anthropic scikit-learn numpy。文件與問題皆為虛構。

import anthropic, numpy as np
from sklearn.cluster import KMeans
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.metrics.pairwise import cosine_similarity

client = anthropic.Anthropic()
MODEL = "claude-sonnet-5"

# 葉節點：手冊切塊（虛構）
leaves = [
    "每季保養：檢查旋角馬達碳刷磨耗與接線端子，記錄絕緣電阻。",
    "每半年保養：旋角備援電源放電測試，記錄電容模組電壓。",
    "每年保養：編碼器校正與三支葉片角度偏差檢查。",
    "每半年保養：檢查旋角減速機油位與油質，異常時取樣送驗。",
    "每年保養：旋角軸承潤滑，依規定油脂量加注。",
    "PT-203 旋角馬達過溫：檢查風道與冷卻風扇，量測 PT100 阻值。",
    "PT-205 旋角馬達煞車異常：檢查煞車線圈電阻與煞車間隙。",
    "進入輪轂前須完成上鎖掛牌（LOTO），並由第二人待命。",
]

def ask(prompt, max_tokens=300):
    msg = client.messages.create(model=MODEL, max_tokens=max_tokens,
        messages=[{"role": "user", "content": prompt}])
    return msg.content[0].text.strip()

def summarize(texts):
    return ask("用繁體中文，把下列段落整合成一則 80 字內的摘要，"
               "保留週期、告警代碼等關鍵資訊，不要加入段落沒有的內容：\n" + "\n".join(texts))

def embed(texts):
    return TfidfVectorizer(analyzer="char", ngram_range=(1, 2)).fit_transform(texts)

def build_tree(texts, group_size=3, max_levels=3):
    nodes = [{"text": t, "level": 0} for t in texts]
    layer = nodes
    for level in range(1, max_levels + 1):
        if len(layer) <= 1:
            break
        k = max(1, round(len(layer) / group_size))
        labels = KMeans(n_clusters=k, n_init=10, random_state=0).fit_predict(
            embed([n["text"] for n in layer]))
        parents = []
        for c in range(k):
            members = [n for n, l in zip(layer, labels) if l == c]
            parents.append({"text": summarize([m["text"] for m in members]), "level": level})
        nodes += parents
        layer = parents                       # 下一輪對「摘要」再分群、再摘要
    return nodes

def retrieve(nodes, query, budget_chars=300):
    # collapsed tree：所有層的節點攤平，依相似度取到預算用完為止（論文以 token 計，這裡用字數近似）
    texts = [n["text"] for n in nodes]
    vec = TfidfVectorizer(analyzer="char", ngram_range=(1, 2)).fit(texts + [query])
    sims = cosine_similarity(vec.transform([query]), vec.transform(texts))[0]
    picked, used = [], 0
    for i in np.argsort(-sims):
        if used + len(texts[i]) > budget_chars:
            break
        picked.append(nodes[i]); used += len(texts[i])
    return picked

tree = build_tree(leaves)
question = "旋角系統有哪些定期保養項目？"
ctx = "\n".join(f"- [L{n['level']}] {n['text']}" for n in retrieve(tree, question))
print(ask(f"只根據下列資料回答；資料不足就說明不足。\n{ctx}\n問題：{question}"))

正式使用時，記得把每個摘要節點對應的子節點記下來，答案才能回溯到原文出處；也要抽查摘要有沒有漏掉週期或把兩個機型的規定混在一起。

⚖️ 與前面課程的比較

基礎 RAG（第 001 堂）父子文件（第 008 堂）情境化檢索（第 009 堂）RAPTOR（本堂）
索引的單位原文切塊小塊檢索、回傳所屬大塊切塊 + LLM 寫的脈絡句切塊 + 多層 LLM 摘要
擅長的問題單一事實需要上下文的細節片段脈絡不明的細節需要整合多段的全局問題
往上看的方向無回到原文的父塊補上文件脈絡抽象化：多段濃縮成摘要
建索引成本最低低每塊一次 LLM 呼叫每群一次，且逐層遞迴

父子文件是「往上拿原文」，RAPTOR 是「往上拿濃縮後的摘要」，可以讀到比單一章節更大範圍的資訊；摘要卻是生成的，不如原文可靠。下一堂的 GraphRAG 也用 LLM 生成摘要，但是先抽出實體與關係再做社群摘要。

⚠️ RAPTOR 常見的坑 / 何時不該用

  • 摘要可能出錯或遺漏：LLM 摘要看似通順，卻可能漏掉週期、把數值寫錯。涉及安全作業或門檻值的問題，答案應回到葉節點原文核對。
  • 建樹成本高：每群、每層都要呼叫 LLM。文件很大時，建樹的時間與費用要先估算。
  • 文件更新要重建：改了一個葉節點，上層摘要就過時。要設計增量更新，或固定週期重建。
  • 分群品質決定摘要品質：不相干的片段被分在同一群，摘要就會東拼西湊。分群方法與群的大小要用自己的資料驗證。
  • 問題多半是單點查詢時不划算：如果幾乎都是查單一告警代碼，混合檢索加重排序更簡單、更便宜。
  • 摘要會稀釋精確詞：料號、告警代碼等精確字串可能在摘要中被省略；collapsed tree 要保留葉節點，並可搭配關鍵字檢索。
風場、機型、手冊內容與數據皆為虛構，實際作業以原廠手冊與現場規範為準。互動範例的摘要為事先手寫、檢索為簡化的 TF-IDF，保養週期與告警代碼僅供教學示範。

延伸閱讀：Sarthi、Abdullah、Tuli、Khanna、Goldie、Manning，〈RAPTOR: Recursive Abstractive Processing for Tree-Organized Retrieval〉（ICLR 2024，arXiv:2401.18059）。

📝 小測驗

RAPTOR 建樹時，由下而上重複的步驟是什麼？

葉節點先分群並各寫一則摘要，摘要再作為下一輪的輸入重複同樣步驟，直到只剩一個根節點或不能再分。

為什麼 RAPTOR 對「旋角系統有哪些定期保養項目」這類問題特別有幫助？

全局問題需要整合多段內容，摘要節點正好濃縮了一群切塊。但摘要是生成的，並不保證比原文精確；涉及安全或數值時仍要回到原文。
