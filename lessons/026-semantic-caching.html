語意快取：相似的問題，直接重用上次的答案

值班室裡，同一個告警常被不同的人用不同的說法問上好幾次，每次都完整跑一遍「檢索＋生成」既慢又貴。語意快取（Semantic Caching）把問題嵌入成向量，和過往問題比相似度，達到門檻就直接回傳上次的答案。省下的是延遲與費用，代價是可能誤命中：措辭很像、答案卻不同。本堂看門檻怎麼取捨，以及怎麼用守門與失效機制降低風險。

🎬 動畫：從每次重算到相似就重用

🧩 重點整理

比的是「問題」與「問題」快取鍵是過往問題的嵌入向量。新問題算出最高相似度，達門檻就回傳當時存下的答案，跳過檢索與生成；沒達就走完整 RAG 並寫入快取。
門檻是取捨太低會誤命中（不同問題拿到同一個答案），太高會漏接（改寫一下就不命中）。門檻取決於嵌入模型與領域，要用自己標註的「同題／不同題」配對校準。
嵌入分不清關鍵差異PT-203 與 PT-230、OW-8 與 OW-6 字面極像，相似度卻很高。告警代碼、機型、料號這類欄位應先精確比對，再交給相似度。
快取會過期手冊更新、技術通報發布，舊答案就可能是錯的。要設 TTL、記錄寫入時的手冊版本，並依機型與權限分區快取。

🧪 互動範例：調門檻，看命中、誤命中與漏接

下面有 4 筆已快取的問題（虛構）。選一個新問題或自己輸入，程式用 TF-IDF 餘弦相似度（第 003 堂的簡化向量）比對快取。切換「不用快取／語意快取／加守門」，並拖動門檻觀察結果；最下方的表會用 6 個預設問題統計目前設定的表現。

這是簡化模擬：真實系統用嵌入模型，相似度的分布不同於這裡的詞元比對；門檻數值不能直接搬用。守門規則：問題與快取問題中的告警代碼、機型必須完全一致。

💻 程式範例（Python）

最小的語意快取：嵌入問題、找最相似的過往問題、達門檻且守門通過才重用。為了不用額外套件就能執行，嵌入以字元二元組向量代替；實際請換成嵌入模型。快取未命中時用 anthropic SDK 生成（需設定 ANTHROPIC_API_KEY）；文件與查詢皆為虛構。

import re, time, math, anthropic
from collections import Counter

THRESHOLD = 0.8        # 要用自己標註的同題／不同題配對校準
TTL = 24 * 3600        # 快取壽命（秒）
MANUAL_VERSION = "OW-8-rev3"   # 手冊更新時改這個，舊快取自動失效
cache = []   # 每筆：{"q", "vec", "codes", "answer", "ts", "ver"}

def embed(text):   # 教學用替身：字元二元組向量；實務請用嵌入模型
    t = re.sub(r"\s+", "", text.lower())
    return Counter(t[i:i+2] for i in range(len(t) - 1))

def cosine(a, b):
    dot = sum(v * b[k] for k, v in a.items())
    na, nb = math.sqrt(sum(v * v for v in a.values())), math.sqrt(sum(v * v for v in b.values()))
    return dot / (na * nb) if na and nb else 0.0

def codes(q):       # 守門：告警代碼與機型必須完全一致
    return frozenset(re.findall(r"[A-Z]{2}-\d{3}|OW-\d", q.upper()))

def rag_answer(question):   # 完整 RAG（此處省略檢索，示意用）
    resp = anthropic.Anthropic().messages.create(
        model="claude-sonnet-5", max_tokens=400,
        messages=[{"role": "user", "content": f"依《OW-8 運維手冊》回答：{question}"}])
    return resp.content[0].text

def ask(question):
    v, c, now = embed(question), codes(question), time.time()
    best, best_s = None, 0.0
    for e in cache:
        if e["codes"] != c or e["ver"] != MANUAL_VERSION or now - e["ts"] > TTL:
            continue               # 守門、版本、過期：任一不符就不能重用
        s = cosine(v, e["vec"])
        if s > best_s: best, best_s = e, s
    if best and best_s >= THRESHOLD:
        return best["answer"], f"命中快取（{best_s:.2f}）"
    ans = rag_answer(question)
    cache.append({"q": question, "vec": v, "codes": c, "answer": ans, "ts": now, "ver": MANUAL_VERSION})
    return ans, "未命中，已完整生成並寫入快取"

for q in ["PT-203 旋角馬達過溫怎麼處理？", "旋角馬達 PT-203 過溫要怎麼排除？", "PT-230 旋角馬達備援電源測試失敗怎麼處理？"]:
    ans, how = ask(q)
    print(q, "→", how)

注意：正式系統通常把快取放在向量資料庫或 Redis 這類儲存層，並為「機型、使用者權限」另設分區鍵。開源專案如 GPTCache 就是以這種思路實作 LLM 回應的語意快取。上面的 embed 只是教學用替身，門檻 0.8 也只是占位數值。

⚠️ 語意快取常見的坑 / 何時不該用

  • 誤命中最危險：答案「看起來很合理」，卻是另一個告警或另一種機型的處理方式。涉及作業安全的問題，門檻要保守，必要時乾脆不快取。
  • 只靠相似度：代碼、型號、數字、否定詞（「可以」與「不可以」）是嵌入的弱項。用規則先精確比對，或改用重排序／LLM 再確認一次。
  • 忘了失效：手冊改版、技術通報、備品料號變更後，舊答案要立刻清除。快取裡至少存寫入時間與手冊版本。
  • 跨權限共用：不同角色（技師、備品管理）可看的文件不同，快取必須依權限分區，否則會洩漏本來看不到的內容。
  • 門檻照抄別人的：0.8、0.9 這類數字只對特定嵌入模型有意義。換模型就要重新校準。
  • 快取被污染：若某次生成的答案是錯的（或被知識庫投毒影響，第 024 堂），之後所有相似問題都會拿到錯答案。要能依回饋刪除單筆快取。
  • 不適合的場景：問題很少重複、答案要看即時資料（當下風速、即時告警狀態），或每次都需要新鮮引用的場景，快取的收益很低、風險相對高。
風場、機型、手冊內容與數據皆為虛構，實際作業以原廠手冊與現場規範為準。互動範例的快取問題、相似度與門檻為教學用簡化模擬，不代表真實嵌入模型的行為。

📝 小測驗

快取中有「PT-203 旋角馬達過溫怎麼處理」，新問題是「PT-230 旋角馬達備援電源測試失敗怎麼處理」，相似度超過門檻。最合理的作法是？

嵌入對代碼、型號這類關鍵差異不敏感，相似度高不代表同一題。先以精確比對守門，不一致就走完整流程。

語意快取的門檻調得很高，最可能出現什麼情況？

門檻高＝很嚴格，只有幾乎一樣的問題才命中，誤命中減少但漏接增加。要在兩者之間用標註資料取捨。
