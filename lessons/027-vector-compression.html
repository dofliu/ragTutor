向量壓縮：Matryoshka 截斷與量化，讓索引小一個數量級

運維手冊、工單與巡檢報告切成百萬個片段後，每個片段的嵌入向量都要放進記憶體，索引的體積與成本很快成為瓶頸。向量壓縮（Embedding Compression）用三種手法縮小它：Matryoshka 截斷（只留前面的維度）、量化（把 float32 改成 int8 或 1 位元），以及兩階段檢索（壓縮向量粗篩、高精度向量重算）。省下的是記憶體與搜尋時間，代價是細微差異可能分不出來。

🎬 動畫：從 20 GB 到 160 MB

🧩 重點整理

體積＝片段數×維度×每維位元組float32 每維 4 位元組、int8 為 1、二元為 1/8。降低維度與降低精度可以相乘，所以壓縮效果很可觀。
Matryoshka：前 n 維自己也能用用 Matryoshka 表示法訓練的模型，把向量截到前 n 維、重新正規化後仍可檢索；一般模型不能這樣砍。
量化：精度換空間int8 約省 4 倍，通常品質損失小；二元量化約省 32 倍，用漢明距離比對、速度很快，但單獨使用品質掉得較多。
粗篩加重算用二元向量多取一些候選（前 k × 倍數），再以高精度向量重新評分取前 k。多數品質能救回來，代價是還要保存高精度向量。

💻 程式範例（Python）

最小的向量壓縮實作：截斷、int8 量化、二元量化，以及「二元粗篩＋高精度重算」。只需要 numpy；為了能直接執行，embed 以雜湊投影代替嵌入模型（不具 Matryoshka 性質，實務請換成支援 Matryoshka 的嵌入模型）。文件與查詢皆為虛構。

import re, zlib
import numpy as np

DOCS = [
    "PT-203 旋角馬達過溫：先停機降溫，檢查冷卻風扇與濾網。",
    "PT-205 旋角馬達煞車異常：檢查煞車線圈供電與間隙。",
    "PT-230 旋角備援電源測試失敗：檢查備援電池電壓與充電迴路。",
    "GB-117 齒輪箱高速軸軸承溫度過高：檢查潤滑油位與油溫。",
    "CV-310 變流器功率模組過溫：檢查水冷迴路流量與散熱器積塵。",
]
D = 256

def embed(text):   # 教學用替身；實務請用嵌入模型（最好支援 Matryoshka）
    v = np.zeros(D, dtype=np.float32)
    toks = re.findall(r"[a-z0-9\-]+|[\u4e00-\u9fff]{2}", text.lower())
    for t in toks:
        for r in range(6):
            h = zlib.crc32(f"{r}:{t}".encode())
            v[h % D] += 1 if (h >> 8) & 1 else -1
    return v

def normalize(x):
    return x / (np.linalg.norm(x, axis=-1, keepdims=True) + 1e-9)

def truncate(x, dims):          # Matryoshka：取前 dims 維並重新正規化
    return normalize(x[..., :dims])

def to_int8(x, scale):          # 純量量化：scale 用資料的最大絕對值校準
    return np.clip(np.round(x * scale), -127, 127).astype(np.int8)

def to_bits(x):                 # 二元量化：大於 0 記 1，並打包成位元組
    return np.packbits(x > 0, axis=-1)

POPCOUNT = np.array([bin(i).count("1") for i in range(256)], dtype=np.int32)
def hamming(qb, db):            # XOR 後數 1 的個數；越小越像
    return POPCOUNT[np.bitwise_xor(db, qb)].sum(axis=-1)

full = normalize(np.stack([embed(d) for d in DOCS]))       # 高精度向量（可放磁碟）
dims = 128
small = truncate(full, dims)
bits = to_bits(small)                                        # 常駐記憶體的壓縮索引
scale = 127 / np.abs(small).max()
int8 = to_int8(small, scale)
print("float32 全維度:", full.nbytes, "B ｜ int8:", int8.nbytes, "B ｜ 二元:", bits.nbytes, "B")

def search(query, k=2, multiplier=5):
    q = normalize(embed(query))
    qb = to_bits(truncate(q, dims))
    cand = np.argsort(hamming(qb, bits))[: k * multiplier]       # 第一階段：二元粗篩
    scores = full[cand] @ q                                    # 第二階段：高精度重新評分
    return [(int(cand[i]), float(scores[i])) for i in np.argsort(-scores)[:k]]

for i, s in search("旋角馬達過溫怎麼處理"):
    print(f"{s:.3f}", DOCS[i])

注意：實務上可用 sentence-transformers 的 truncate_dim 參數與 quantize_embeddings 函式處理截斷與量化，向量資料庫（如 Qdrant、Weaviate、Milvus 等）也多內建純量或二元量化選項，細節請查各產品文件。上面的 embed 只是教學替身，維度與倍數也是占位數值。

⚠️ 向量壓縮常見的坑 / 何時不該用

  • 用沒訓練過的模型硬截斷：只有以 Matryoshka 方式訓練的模型，前 n 維才保有語意；一般模型砍掉後半段，品質可能掉很多。先看模型的說明文件。
  • 只看體積不量品質：壓縮倍率再漂亮，召回掉了就沒意義。要用自己的查詢與標註結果量「召回率」與「前幾名是否正確」。
  • 代碼與型號最先被混淆：PT-203 與 PT-230 這類只差幾個字元的內容，在低維度、1 位元時最容易分不出來。這類查詢可搭配第 004 堂的關鍵字檢索，或第 005 堂的重排序。
  • 忘了留高精度向量：想做重新評分，就必須另外保存高精度向量（磁碟或物件儲存）；否則二元索引的誤差無法補救。
  • 量化範圍沒校準：int8 的縮放比例若被少數極端值拉大，大多數維度會只用到很小的整數範圍，白白浪費精度。
  • 換模型沒重做：維度、量化範圍與倍數都與嵌入模型綁定，換模型就要重新壓縮並重新驗證。
  • 不適合的場景：知識庫只有幾萬個片段時，記憶體本來就不是問題，壓縮的收益有限，卻多了複雜度與品質風險。
風場、機型、手冊內容與數據皆為虛構，實際作業以原廠手冊與現場規範為準。互動範例的向量為雜湊投影的教學用簡化模擬，不代表真實嵌入模型的行為。

📝 小測驗

想把一般（未用 Matryoshka 訓練）的嵌入模型輸出直接截成前 128 維來省空間，最大的風險是什麼？

Matryoshka 表示法在訓練時就要求前 n 維自成一個可用的向量；沒有這樣訓練的模型，資訊分散在各維度，直接截斷可能損失很多。

二元量化的向量搭配「重新評分」的作法，是怎麼運作的？

二元向量又小又快，適合大範圍粗篩；高精度向量只讀少數候選，補回粗篩損失的品質，但需要另外保存高精度向量。
