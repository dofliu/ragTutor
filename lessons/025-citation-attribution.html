RAG 引用與歸因：讓每一句答案都能回頭查證

RAG 的賣點是「答案有依據」，但如果技師看不出哪一句出自手冊的哪一節，這份依據就形同虛設。引用與歸因（Citation / Attribution）要求模型在每一句後面標註來源，再由程式驗證：編號存在嗎？被引用的片段真的支持這句話嗎？本堂看這兩關怎麼做、怎麼用引用召回與精確度量化，以及沒有依據的句子該怎麼處理。

🎬 動畫：從黑箱答案到可查證的答案

🧩 重點整理

引用 = 讓答案可以被查證RAG 的價值是「有依據」。把依據標在每一句後面，技師就能回頭核對手冊原文，而不是整段相信或整段不信。
先編號，再標註檢索片段進提示前由系統編號（附文件、章節對照表），要求模型在句尾用 [編號] 標註；編號不要讓模型自己發明。
兩關驗證第一關：句尾編號是否在取回清單內（集合比對，很便宜）。第二關：被引用的片段是否真的支持該句（NLI、LLM 評審或詞彙重疊）。只過第一關仍可能是「張冠李戴」。
量化與處置ALCE 論文提出以引用召回與引用精確度衡量引用品質。無依據的句子可移除、改成「手冊未載明」或轉人工；事實為真但檢索內容沒寫，也算無依據。

🧪 互動範例：驗證引用，看哪些句子站得住腳

下面是模型對三個問題的答案（虛構，每句都附了 [編號]，其中混入了無依據的句子、錯誤的編號與不存在的編號）。切到「驗證」模式，程式會逐句檢查：編號是否存在、被引用片段與該句的字詞覆蓋率是否達門檻，並算出引用召回與精確度。

這是簡化模擬：覆蓋率＝句子的詞元（中文二元組）有多少比例出現在被引用的片段；真實系統會用 NLI 或 LLM 評審判斷語意是否蘊含。調高門檻會更嚴格，但同義改寫的句子也更容易被誤判為不支持。

模式：
答案（逐句）
檢索片段清單（虛構《OW-8 運維手冊》）

💻 程式範例（Python）

最小的「編號 → 標註 → 兩關驗證」。為了不用額外套件就能跑驗證，支持度用字元二元組覆蓋率代替 NLI；實際系統可換成 NLI 模型或 LLM 評審。文件為虛構，回答用 anthropic SDK（需設定 ANTHROPIC_API_KEY）。

import re, anthropic

# 檢索到的片段：編號由系統產生，並保留與文件、章節的對照
CHUNKS = {
    1: ("手冊 §4.2", "PT-203 旋角馬達過溫：先停機並降溫，檢查冷卻風扇與濾網，確認繞組溫度後才可復歸。"),
    2: ("手冊 §4.5", "更換旋角馬達前必須先執行上鎖掛牌，並確認葉片已順槳鎖定。"),
    3: ("工單 WO-2026-0412", "旋角馬達故障，現場檢查冷卻風扇積塵，清潔後復歸，已確認上鎖掛牌紀錄。"),
}

SYSTEM = ("你是風場運維助理。只能根據 <片段> 回答；每一句句尾用 [編號] 標註來源，"
          "一句可標多個編號。片段沒寫的內容不要回答，請說「手冊未載明」。")

def ask(question):
    ctx = "\n".join(f'<片段 編號="{i}">{t}</片段>' for i, (_, t) in CHUNKS.items())
    resp = anthropic.Anthropic().messages.create(
        model="claude-sonnet-5", max_tokens=500, system=SYSTEM,
        messages=[{"role": "user", "content": ctx + f"\n\n問題：{question}"}])
    return resp.content[0].text

def bigrams(s): return {s[i:i+2] for i in range(len(s) - 1)}

def support(sentence, ids):   # 第二關：被引用片段覆蓋了句子多少內容（簡化版）
    s = bigrams(re.sub(r"\[\d+\]|[，。、：；\s]", "", sentence))
    cited = set().union(*(bigrams(CHUNKS[i][1]) for i in ids if i in CHUNKS))
    return len(s & cited) / max(len(s), 1)

def verify(answer, thr=0.6):
    report, ok_cites, all_cites = [], 0, 0
    for sent in re.split(r"(?<=\])|(?<=。)", answer):
        ids = [int(x) for x in re.findall(r"\[(\d+)\]", sent)]
        if not sent.strip(): continue
        bad = [i for i in ids if i not in CHUNKS]           # 第一關：編號存在嗎
        score = support(sent, ids)
        verdict = "無效引用" if bad or not ids else "支持" if score >= thr else "不支持"
        all_cites += len(ids); ok_cites += len(ids) if verdict == "支持" else 0
        report.append((verdict, round(score, 2), sent.strip()))
    recall = sum(r[0] == "支持" for r in report) / max(len(report), 1)
    precision = ok_cites / max(all_cites, 1)
    return report, recall, precision

answer = ask("PT-203 旋角馬達過溫怎麼處理？")
report, recall, precision = verify(answer)
for row in report: print(row)
print(f"引用召回 {recall:.0%}，引用精確度 {precision:.0%}")

注意：這裡的 support 只是教學用的近似，會誤判同義改寫；正式使用請換成 NLI 模型或 LLM 評審，並抽樣人工檢查判定結果。部分 API（例如 Anthropic 的 Citations 功能）可以直接回傳引用位置，省去自己解析句尾編號，但「引用是否真的支持該句」仍建議自行抽查。

⚠️ 引用與歸因常見的坑 / 何時不該用

  • 把「有附引用」當成「有依據」：模型可能引用不相干的片段，甚至編出不存在的編號。至少要做編號存在檢查，最好再檢查內容支持。
  • 編號由模型自己決定：編號與片段的對應必須由系統產生並保存，不要事後靠模型回憶「剛剛第幾段」。
  • 引用粒度太粗：整份手冊當一個出處，技師還是要自己翻幾十頁。引用到章節、段落甚至句子，才真的能核對。
  • 判定器也會錯：詞彙重疊會誤判同義改寫，NLI 模型對長片段、數字與否定句也可能出錯（ALCE 論文也指出其 NLI 判定與人工評估有落差）。要抽樣人工檢查。
  • 「真的」不等於「有依據」：模型說的可能是事實，但取回的資料沒寫。歸因檢查問的是證據，不是真偽；要補知識就回頭改善檢索（第 014 堂）或補資料。
  • 出處本身可能是錯的：引用只能證明答案來自某份文件；文件是過時版本、被污染（第 024 堂）或機型不符時，答案仍然是錯的。
  • 不是所有場景都需要：閒聊式、創意型問答，或答案本身一眼可驗證的場景，逐句驗證的成本不一定划算；但會影響作業安全的答案（上鎖掛牌、復歸條件）就該有。
風場、機型、手冊內容與數據皆為虛構，實際作業以原廠手冊與現場規範為準。互動範例的答案與檢索片段為教學用虛構示意，覆蓋率驗證是簡化模擬，不代表真實模型的引用行為。

📝 小測驗

答案句尾的引用編號 [7] 不在本次取回的片段清單中。這代表什麼？

編號必須對應到系統這次放進提示的片段；不在清單內就是無效引用。這一關只需要集合比對，不需要模型。

一句話引用的編號存在，但被引用的片段完全沒提到這件事，該怎麼判定？

這就是第二關「支持度檢查」要抓的情況。事實為真但取回資料沒寫，仍是無依據；處理方式是移除、改成「手冊未載明」或補資料。
