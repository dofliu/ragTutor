第 020 堂高階約 20 分鐘

多模態 RAG：圖片、表格與 PDF 版面

技師問：「旋角馬達的煞車線圈接在哪個端子？」答案只畫在手冊的配線圖上；問「PT-211 代表什麼」，答案在告警代碼表格裡；問葉片前緣的缺陷，答案在巡檢照片上。純文字 RAG 抽文字時，表格的欄列會錯位，圖與照片則整個消失。多模態 RAG（multimodal RAG）有兩條路：把表格與圖先轉成文字再索引，或直接嵌入整頁影像，命中後把原圖交給視覺語言模型（VLM）回答。

🎬 動畫：圖表裡的答案怎麼檢索

🧩 重點整理

答案不一定在文字裡表格、配線圖、爆炸圖與巡檢照片常帶有關鍵資訊；只抽文字會讓表格欄列錯位、圖片整個消失。
路線 A：先轉成文字表格整張保留並逐列補欄名，圖片用視覺模型寫圖說（附頁碼、原圖路徑），再進既有的文字索引，檢索流程不必改。
路線 B：嵌入整頁影像ColPali 一類做法把頁面影像編成多向量、用延遲互動比對，省掉 OCR 與版面解析；回答時再把頁面圖交給 VLM。
留下可核對的出處不論哪條路線，答案都應附頁碼與圖號並保留原圖；圖說可能看錯，要抽樣人工核對。

🧪 互動範例：只抽文字 vs 轉成文字（含圖說品質）

下面是虛構《OW-8 運維手冊》旋角系統幾頁的內容：文字段落、告警表格、兩張圖、一張巡檢照片。「純文字抽取」只拿得到一般 PDF 轉文字的結果（表格欄列黏在一起、圖只剩零散標籤、照片沒有文字）；「轉成文字」則把表格逐列補欄名，並依你選的圖說品質替圖片與照片補上說明。檢索用 BM25，取前 3 筆。請切換設定與問題，看答案有沒有被撈到、撈到的內容讀不讀得懂。這裡只模擬路線 A；路線 B 需要真正的視覺模型，無法在瀏覽器裡示範。

💻 程式範例（Python）

用 anthropic SDK 做路線 A：表格逐列補欄名、圖片請模型寫圖說，每個元素存成一筆（含頁碼與原圖路徑）；回答時把命中的原圖一併交給模型（pip install anthropic）。文字與表格皆為虛構，figs/p37_fig2.png 請換成你自己的圖；檢索用最簡單的二字詞重疊代替真正的向量檢索。

import base64
import anthropic

client = anthropic.Anthropic()
MODEL = "claude-sonnet-5"

# 1) 虛構的手冊元素：表格列與一張配線圖（圖片路徑請換成自己的檔案）
TABLE = [("PT-203", "旋角馬達過溫", "4.3.1"), ("PT-205", "旋角馬達煞車異常", "4.3.2")]
FIGURES = [{"page": 37, "path": "figs/p37_fig2.png", "hint": "圖 4-2 旋角馬達配線圖"}]

def image_block(path):
    data = base64.standard_b64encode(open(path, "rb").read()).decode()
    return {"type": "image", "source": {"type": "base64", "media_type": "image/png", "data": data}}

def describe(path, hint):                       # 圖 → 可檢索的說明文字
    prompt = f"這是《OW-8 運維手冊》的{hint}。請用繁體中文寫出零件名稱、端子或編號與對應關係；看不清楚請寫「無法辨識」，不要猜。"
    resp = client.messages.create(model=MODEL, max_tokens=400, messages=[
        {"role": "user", "content": [image_block(path), {"type": "text", "text": prompt}]}])
    return resp.content[0].text

# 2) 建索引：每個元素一筆，附頁碼與原圖路徑
items = [{"page": 36, "text": "進入輪轂前須完成上鎖掛牌並確認風速", "image": None}]
items += [{"page": 36, "text": f"告警代碼 {c}，意義 {m}，處置 見 {s}", "image": None}   # 表格逐列補欄名
          for c, m, s in TABLE]
items += [{"page": f["page"], "text": describe(f["path"], f["hint"]), "image": f["path"]} for f in FIGURES]

def bigrams(s):
    s = "".join(s.split())
    return {s[i:i + 2] for i in range(len(s) - 1)}

def search(query, k=3):                          # 簡化的檢索：二字詞重疊數
    qg = bigrams(query)
    scored = [(len(qg & bigrams(it["text"])), it) for it in items]
    return [it for n, it in sorted(scored, key=lambda x: -x[0])[:k] if n > 0]

# 3) 生成：命中的元素若有原圖，連圖一起交給模型
def answer(question):
    content = []
    for it in search(question):
        content.append({"type": "text", "text": f"[第 {it['page']} 頁] {it['text']}"})
        if it["image"]:
            content.append(image_block(it["image"]))
    content.append({"type": "text", "text": f"只根據以上資料回答，並註明頁碼：{question}"})
    resp = client.messages.create(model=MODEL, max_tokens=512, messages=[{"role": "user", "content": content}])
    return resp.content[0].text

print(answer("旋角馬達的煞車線圈接在哪個端子？"))

注意：路線 B（整頁影像嵌入）需要專用的多向量檢索模型與索引，例如論文提出的 ColPali，不是幾行程式能示範的；有興趣可從該論文與其開源實作開始。無論哪條路線，圖說或回答都要保留頁碼，讓人能回到原頁核對。

⚖️ 與前面課程的比較

基本 RAG（第 001 堂）ColBERT（第 018 堂）轉成文字（本堂路線 A）整頁影像嵌入（本堂路線 B）
索引的是什麼文字塊的單一向量文字塊的逐詞向量文字、表格列與圖說，再走文字索引頁面影像的區塊向量（多向量）
表格與圖片抽文字時走樣或消失同左，仍只處理文字靠轉換品質；沒寫進圖說的細節找不到連同版面一起編碼，不需轉換
索引與查詢成本最低索引大、比對較貴索引小；建索引時要呼叫 VLM 寫圖說索引大；回答時要把圖送給 VLM
主要風險漏掉圖表中的答案儲存與實作複雜度圖說看錯或漏看需要專用模型與基礎設施，圖上小字可能看不清

路線 B 的比對方式其實就是第 018 堂的延遲互動，只是被比對的單位從「文字詞」換成「頁面影像的區塊」。先確認文字索引做不到，再考慮升級。

⚠️ 多模態 RAG 常見的坑 / 何時不該用

  • 表格被切斷：切塊時把表格從中間切開，欄名與數值分家。表格要整張保留、逐列補欄名，太長的表可分段並在每段重複表頭。
  • 圖說看錯或漏看：模型可能把端子編號讀錯。提示要要求「看不清楚就寫無法辨識」，並抽樣與原圖比對；安全相關的接線資訊一律以原圖與原廠手冊為準。
  • 只存圖說、不存原圖：命中後沒有原圖可看，就無法核對。索引要記頁碼、圖號與原圖路徑，必要時生成時把原圖一併送給模型。
  • 掃描品質不佳：歪斜、模糊、手寫註記會讓 OCR 與視覺模型都出錯；先確認輸入品質，再談檢索方法。
  • 成本被低估：用 VLM 替每張圖寫說明、或每次回答都送圖，成本都比純文字高；先用評估集確認值不值得。
  • 圖片多半是裝飾：若手冊的圖大多只是示意、關鍵資訊都有寫在文字裡，轉文字就夠了，不必上多模態。
  • 不要拿答案去當現場作業依據：配線、扭力、安全步驟等資訊，模型讀圖的結果只能當檢索線索，作業前要回到原圖與規範確認。
風場、機型、手冊內容與數據皆為虛構，實際作業以原廠手冊與現場規範為準。互動範例中的頁碼、圖號、端子與巡檢結果都是虛構示範，不可作為實際接線或維修依據。

延伸閱讀：Faysse 等，〈ColPali: Efficient Document Retrieval with Vision Language Models〉（arXiv:2407.01449，提出直接嵌入頁面影像的檢索與 ViDoRe 視覺文件檢索基準）；Radford 等，〈Learning Transferable Visual Models From Natural Language Supervision〉（CLIP，arXiv:2103.00020，把圖與文字映射到同一個向量空間）。

📝 小測驗

用一般 PDF 轉文字建立索引，下列哪項最可能發生？

純文字抽取只拿得到「字」：表格結構容易跑掉，圖片與照片多半只剩零散標籤或完全沒有文字。文字段落反而是它最擅長的。

「整頁影像嵌入」（ColPali 一類做法）和「轉成文字」相比，主要差別是什麼？

影像嵌入直接處理頁面影像，不必先轉成文字，但仍需要視覺語言模型來編碼與回答，多向量索引也比單一向量大。
